# Feature Specification: 业绩评分项案例推荐精准准入（品类 + 金额门槛 + 资格项回退）

**Feature Branch**: `agent/gemini/fix-perf-case-admission`（Spec 目录：`064-perf-case-admission`）

**Created**: 2026-09-16

**Status**: Draft

**Input**: 用户反馈：「AI 智能案例推荐里，评分项选择类似业绩时推荐结果不准——现在推的都是人员相关的。按要求应推荐办公业绩不低于 2000 万、工业品业绩不低于 4500 万元的案例；如果评分项没有（具体门槛），要去资格项中找相关的案例。」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 业绩评分项只推荐符合条件的业绩案例 (Priority: P1)

投标人员在项目详情页「AI 智能案例推荐」抽屉选择业绩类评分项（如「类似业绩」「3 同类项目业绩」）。
评分项原文往往只是指针（“详见初步评审第 7 条供应商资格”），真实品类与金额门槛写在资格项里。
用户期望：推荐列表不再出现人员/技术等无关案例，并且优先给出满足资格项品类与金额门槛的业绩案例。

**Why this priority**: 这是用户本次反馈的核心缺陷——错误类别的案例会误导投标人员复用内容。

**Independent Test**: 构造「业绩评分项 + 资格项双门槛 + 人员案例 + 合规业绩案例」数据集，调用推荐接口断言：人员案例不出现；达门槛案例出现且排序优先；低于门槛的候选被排除。

**Acceptance Scenarios**:

1. **Given** 资格项要求“办公用品年度供应业绩、任意自然年发票累计金额不低于 2000 万元”，**When** 用户选择业绩评分项，**Then** 推荐结果不含人员类案例，并展示具备办公用品品类且金额证据 ≥2000 万元的案例。
2. **Given** 资格项要求“标准工业品不低于 4500 万元”，**When** 用户选择业绩评分项，**Then** 金额证据 ≥4500 万元的工业品案例被推荐；金额证据明确低于门槛的候选被排除。
3. **Given** 资格项分列两条业绩条款（办公 2000 万；工业 4500 万），**When** 生成推荐，**Then** 两条门槛同时生效（不再只取第一条）。
4. **Given** 某案例品类命中但正文未提及金额，**When** 生成推荐，**Then** 该案例作为降级候选保留（避免召回归零），但明确低于门槛的案例不得进入任何层级。
5. **Given** 评分项与资格项都没有品类/金额信息，**When** 选择业绩评分项，**Then** 仅推荐具备业绩证据的案例，人员简历/团队类案例不出现。

---

### User Story 2 - 未选评分项时回退资格项检索 (Priority: P2)

项目尚未解析出可用评分项（或用户未选择评分项），但标书资格项中存在业绩要求时，
默认推荐应能利用资格项中的业绩要求（品类/金额）作为检索与过滤上下文。

**Why this priority**: 覆盖“评分项没有”的显式要求，避免无评分项时只能给泛化列表。

**Independent Test**: 构造无 scoreItemId 的推荐请求 + 资格项业绩要求，断言推荐结果按资格项业绩要求过滤；资格项无业绩要求时保持现有行为。

**Acceptance Scenarios**:

1. **Given** 项目未选择评分项且资格项含“大型集团级办公用品年度供应业绩（≥2000 万）”，**When** 请求默认推荐，**Then** 结果中优先展示命中品类与门槛证据的案例，且不出现人员类案例。
2. **Given** 项目未选择评分项且资格项无任何业绩条款，**When** 请求默认推荐，**Then** 行为与现状保持一致（不因本次变更丢失召回）。

---

### User Story 3 - 混合类别文本按业绩优先归类 (Priority: P2)

存量与新增案例的类别标签存在「资质业绩」这类混合文本。与业绩评分项匹配时应归为业绩大类并参与加权；
纯资质证书类文本（ISO/AAA/等级证书）仍应归为资质大类。

**Why this priority**: 分类错位会让真正的业绩案例被反降权，是“推荐不准”的隐藏成因之一。

**Independent Test**: 纯函数断言：`资质业绩`→业绩；`资质等级证书`→资质；不影响现有人员/技术/商务分类断言。

**Acceptance Scenarios**:

1. **Given** 候选案例类别为「资质业绩」，**When** 与业绩评分项比对，**Then** 判定为业绩大类，可获得类别一致加权。
2. **Given** 候选案例类别为「资质等级证书」（无“业绩”字样），**When** 与资质类评分项比对，**Then** 仍判定为资质大类。

---

### Edge Cases

- 资质证书类文本包含“业绩”二字（如“质量管理体系认证及业绩证明”）时的归类边界；
- 金额写法多样：`2000万元`、`2000万`、`0.2亿元`、`2,000万元`、区间与“不低于/不少于”；
- 资格项文本与评分项详情均为空或只有指针引用；
- 标书快照缺失（取不到资格项）时，业绩评分项仍不得放行人员类案例；
- 存量案例没有金额字段与金额文本时的降级分层；
- 同一门槛条款内出现多个品类与多个金额时的配对关系。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 业绩类评分项推荐 MUST 排除不具备业绩证据的候选（人员/团队/简历等纯人员类案例不得出现）。
- **FR-002**: 系统 MUST 从资格项列表与标书资格审查/初步评审章节中提取**全部**实质业绩条款（不得命中第一条即返回）。
- **FR-003**: 系统 MUST 将业绩条款中的品类与金额门槛结构化，金额统一归一为万元。
- **FR-004**: 候选案例存在明确低于门槛的金额证据时 MUST 被排除；金额证据达到门槛的候选 MUST 优先于无金额证据的候选。
- **FR-005**: 品类或金额证据缺失时 MUST 降级保留业绩信号候选（不得因缺少金额证据导致整体空结果，也不得放行无关类别）。
- **FR-006**: 未选择评分项且资格项存在业绩要求时，系统 MUST 以资格项业绩要求作为推荐上下文（过滤/加权）；资格项无业绩要求时保持现状。
- **FR-007**: 「资质业绩」等混合类别文本 MUST 按业绩优先归类；纯资质文本（无“业绩”字样） MUST 仍归类为资质。
- **FR-008**: 推荐理由 MUST 展示命中的品类/门槛依据（沿用现有加分理由体系）。
- **FR-009**: 推荐接口契约与前端展示阈值 MUST 保持不变（前端零改动）。

### Key Entities *(include if feature involves data)*

- **业绩要求（PerformanceRequirement）**: 来自资格项/资格审查章节的实质业绩条款；包含原文、核心特征词、品类集合、金额门槛集合（品类-金额对，万元）。
- **品类-金额门槛（CategoryThreshold）**: 单一品类与其最低金额（万元）的配对。
- **候选案例（KnowledgeCase）**: 历史应答片段，含类别、要求原文、应答正文、中标结果与质量分；本次所需“业绩证据”从应答正文与要求原文中提取。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 5 组构造数据集（人员干扰 + 合规业绩 + 低额业绩）上，业绩评分项推荐结果中人员类案例占比 0%。
- **SC-002**: 双门槛场景（办公 2000 万 / 工业 4500 万）下，两条门槛均参与准入判定（可重放的纯函数断言）。
- **SC-003**: 品类命中但无金额证据的业绩案例仍可被召回（降级分层生效，不出现“0 结果”回归）。
- **SC-004**: 存量「资质业绩」案例与业绩评分项的大类一致判定命中率为 100%（单测断言）。
- **SC-005**: 现有 casework 模块测试全绿，架构与行数门禁全绿。

## Assumptions

- 金额门槛证据只能来自案例文本（`knowledge_case` 当前无金额/业绩品类字段）；新增数据库字段不在本次范围，登记为技术债。
- 前端不改（保持匹配度 ≥50 展示门槛与现有卡片交互）。
- 当所有候选都不满足门槛且无业绩信号时，允许返回空列表（诚实降级，不伪造）；只要有业绩信号候选则必须保留。
- 资格项快照缺失时，仅能依赖业绩信号准入（无法做品类/金额验证）。
- 分类修复只调整类别推断优先级，不迁移存量标签数据。
- 交付目标为 working_tree（不建 PR、不部署）。
