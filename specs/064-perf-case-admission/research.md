# Phase 0 Research: 业绩评分项案例推荐精准准入

**Feature**: specs/064-perf-case-admission | **Date**: 2026-09-16

## R1. 金额门槛如何解析（资格项文本 → 结构化门槛）

- **Decision**: 将条款文本按“数字外逗号/分号/句号/换行”分段；分段内金额按“前向『的』标记 → 最近前序品类 → 最近后序品类”归属；缺少金额的品类段向后寻找最近金额段（跨句衔接）；同分段单金额视为多品类共享；统一换算为万元。
- **Rationale**: 真实标书既有「品类+金额」同段形态，也有「先枚举品类、后逐项金额」与「金额+的+品类」形态；纯最近距离会在“A 金额，B 金额”链上把 A 的金额配给 B（审查轮实测反例），因此引入方向标记与前序优先规则。
- **Alternatives considered**:
  1. 全文档正则直接抓数字 → 否：会混入年份/数量/评分分值，假阳性高；
  2. NLP 依赖解析 → 否：引入重型依赖，违反 FP-Java 与 Boring Proven Patterns；
  3. 只保留原文做字符串包含 → 否：无法做“低于门槛必拒”的数值判定（现状缺陷）。

## R2. 候选案例的金额证据如何提取与比较

- **Decision**: 候选全文（要求原文 + 应答正文 + 评分点标题）按同一分段规则提取金额；仅采信带单位（元/千/万/亿）的数字，区间取整取下界，带“不超过/以下/以内”上限修饰的金额忽略；同品类多金额取最大值；同分段单金额视为共享。
- **Rationale**: 案例切片中“单笔 50 万、年度累计 2600 万”与“累计发票金额 4500 万元”并存，取最大值才能反映真实累计业绩；对上限修饰的忽略避免把“不超过 2000 万”当成下限门槛。
- **Alternatives considered**:
  1. 全文最大金额直接比较 → 否：不同品类的金额会串台；
  2. 仅比较文本是否包含门槛原文（如“2000万元”）→ 否：会把恰好复述门槛的案例误判为达标，且无法判定 4500 万是否满足 2000 万门槛。

## R3. 准入分层与降级策略（避免再次“0 结果”回归）

- **Decision**: 分层准入，编排层保留可用最优集合：
  - tier-1 门槛达成（业绩证据 + 品类命中 + 金额证据 ≥ 对应门槛）；
  - tier-2 品类命中（业绩证据 + 品类命中，缺失金额证据）；
  - tier-3 业绩信号（仅业绩证据词，无品类/金额信息时即为该层）。
  **保留规则：存在 tier1/tier2 时保留全部 tier1+tier2；均无时降级保留 tier3；全部无业绩证据才返回空。**
  金额证据明确低于门槛的候选在任何层级都被一票否决。
- **Rationale**: 只保留 tier1 会丢弃更高匹配分的 tier2 候选并叠加前端 ≥50 过滤造成空列表（审查轮实测：tier1 得分 36、tier2 得分 79 被互斥丢弃）；保留 tier1+2 既守住“不放行无关类别”，又避免 0 结果与高分候选丢失。
- **Alternatives considered**:
  1. 严格排除一切无金额证据候选 → 否：真实导入切片大量无金额文本，会重现“0 结果”缺陷（lessons #367 的历史教训）；
  2. 仅加权不过滤 → 否：即本次缺陷本身（人员/低额案例仍可越过前端 ≥50 门槛）；
  3. tier 硬过滤只留最优一层 → 否：上述空列表与高分丢弃问题。

## R4. 混合类别「资质业绩」归类顺序

- **Decision**: `classifyText` 中把 PERFORMANCE 判定前移到 QUALIFICATION 之前（保留 PERSONNEL 最高优先级）；纯资质文本（无“业绩”字样）不受影响。
- **Rationale**: 存量标签由 `extractCategory` 机械产出「资质业绩」，当前“资质优先”使真业绩案例被判 QUALIFICATION，丢失类别一致 +10；调整顺序可同时修复存量与新增数据，无需数据迁移。
- **Alternatives considered**:
  1. 迁移存量标签字段 → 否：无法区分证书类与业绩类来源，且引入迁移锁与并行冲突；
  2. 修改 `extractCategory` 输出标签 → 否：存量数据仍是旧标签，需双轨兼容，收益低于成本。

## R5. 资格项回退触发条件

- **Decision**: 两类触发：①评分项被判为业绩类且能取到资格项 → 以资格项实质条款为准（含品类/门槛）；②未选择评分项（scoreItem 为空）且**无关键词检索**、资格项存在业绩条款 → 以资格项条款作为推荐上下文（Tier-1/2/3 准入 + 现有加分）；关键词检索路径保持原行为。非业绩评分项不劫持资格项。
- **Rationale**: 直接对应“评分项没有，要去资格项中找相关的案例”；同时避免技术/商务评分项被业绩案例污染。
- **Alternatives considered**:
  1. 任何评分项都尝试资格项回退 → 否：会改变技术/商务评分项的推荐语义；
  2. 只在评分项为空时回退 → 否：无法覆盖用户实际场景（业绩评分项 + 指针式详情）。

## R6. 多条款合并的边界保护

- **Decision**: 合并全部实质条款（去重），上限 5 条 / 4000 字符；关键词、品类、门槛取并集。
- **Rationale**: 防止标书资格章节超长导致打分上下文膨胀与展示关键词槽位挤占；5 条覆盖“双标包双门槛”的典型形态。
- **Alternatives considered**: 无限合并 → 否：关键词宽泛化会稀释最相关条款的区分度。

## R7. 准入判定的落点

- **Decision**: 判定函数放 `domain/policy/PerformanceCaseAdmissionPolicy`；候选过滤编排放 `ScoreItemCaseRecommendAppService`（纯核心返回判定结果，外壳层执行过滤/日志）。`ScoreItemCaseMatchPolicy` 既有权重与打分链路不动。
- **Rationale**: 遵守 Split-First 与 300 行棘轮（MatchPolicy 已 298 行）；纯函数可 100% 单测；编排层保留权限校验与取数职责。
- **Alternatives considered**: 在 `ScoreItemCaseMatchPolicy.evaluate` 内做过滤 → 否：文件超限且打分语义被污染。
