# 实施计划

## 技术背景与宪章检查

现有证据写入以事务保存；实体与数据库均将 explanation 限为 255 字。复核查询和提交各自查项目最新 PARSE 任务，命令缺少任务身份。遵守纯核心/命令外壳、真实 API、先失败测试、Flyway 正反迁移和最小改动。

## 方案

1. 将 explanation 扩至 TEXT，实体映射同步；迁移仅扩容该列。回滚在有超过 255 字的数据时拒绝缩容，防止截断。
2. 复核命令增加页面任务标识；提交时与最新任务 ID 比对，且只允许已完成、有候选的任务。旧调用方同步传入标识。
3. 解析失败时刷新界面复核快照，清掉旧候选；采纳拒绝时刷新并展示准确错误。
4. PARSE 任务创建和候选采纳共用项目行锁；采纳在锁内当前读最新任务，并拒绝已采纳任务的重复发布。

## 风险与验证

先用后端服务测试覆盖旧任务与失败任务，再验证当前任务成功；前端测试覆盖提交标识、失败刷新。检查迁移前后字段容量及回滚拒绝截断。测试服项目 1385 的在线重解析和采纳属于后续部署验收，不在本地代码修复内。
隔离 MySQL 测试覆盖 500 字说明读回、缩容失败不截断与双事务锁顺序；Docker 不可用时不得把跳过的容器测试记为通过，可用独立临时本机 MySQL 库补充 SQL 实测。回滚失败后执行器必须停止并关闭该连接。
