# 修复评分标准采纳与解析任务错位

**Feature Branch**: `agent/claude/score-adoption-1385`
**Created**: 2026-09-22
**Status**: Ready

## User Scenarios & Testing

### User Story 1 - 解析证据可靠保存 (Priority: P1)

招标文件的评分证据说明较长时，解析仍能完整保存候选项，供用户复核。

**Acceptance Scenarios**:

1. Given 说明超过 255 字，When 保存解析结果，Then 说明和候选项完整可读，不因字段长度导致整次解析失败。

### User Story 2 - 采纳当前复核内容 (Priority: P1)

用户采纳页面所见候选项时，系统只接受与当前解析任务一致且成功完成的候选。解析任务已更新或失败时，提示重新查看最新结果，不发布过期候选。

**Acceptance Scenarios**:

1. Given 当前已完成的复核任务和合计闭合的候选项，When 一键采纳，Then 正式评分项与该任务候选一致。
2. Given 页面显示旧任务候选而最新任务失败，When 一键采纳，Then 无正式项写入并明确提示任务已变化。

### User Story 3 - 错误可理解 (Priority: P2)

解析失败时页面撤掉过期复核候选并显示解析失败原因；采纳业务校验失败时，用户看到具体可操作原因。

**Acceptance Scenarios**:

1. Given 新任务解析失败，When 页面刷新，Then 不展示旧候选采纳按钮，且显示失败信息。
2. Given 后端拒绝过期候选，When 提交，Then 提示当前解析任务已变化，而非泛化系统状态冲突。

## Edge Cases

- 重复提交不得发布两套评分项。
- 解析任务创建与采纳并发时，必须在同一项目事务锁下判定任务身份；已采纳任务的重复请求不得再次重建正式项。
- 候选事实为空、解析中、解析失败均不得采纳。
- 旧版不含任务标识的复核请求不得误采纳最新任务。

## Requirements

- FR-001: 保存评分证据说明时不得因超过 255 字而丢失整次解析。
- FR-002: 采纳请求必须绑定页面复核任务并核对当前任务身份和成功状态。
- FR-003: 失败的解析任务使页面旧候选失效。
- FR-004: 业务失败返回具体、适合用户阅读的原因。

## Success Criteria

- SC-001: 500 字说明可完整保存并读回。
- SC-002: 旧任务候选提交对正式评分项的写入次数为 0。
- SC-003: 当前有效任务的采纳可一次完成，正式项合计等于已核对总分。

## Assumptions

- 新解析任务一旦创建，旧任务候选不再代表当前页面可采纳内容；用户应在新解析成功后复核最新候选。
