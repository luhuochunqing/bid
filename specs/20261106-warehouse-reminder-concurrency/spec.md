# Feature Specification: 修复仓库到期并发重复消息
**Feature Branch**: `agent/trae/warehouse-reminder-investigation`
**Created**: 2026-11-06
**Status**: Approved for implementation by 用户“立刻修复”
**Input**: 仓库提醒部分一天同一消息两次。
## User Scenarios & Testing
### US1 同一仓库提醒仅生成一次 (P1)
两个实例同时扫描同一到期仓库，过去24小时无同类通知：仅创建一条。已有提醒、关仓或未进入提醒范围则跳过。事务失败不留下半成品；后续扫描可正常补发。
### US2 同一投递任务仅执行一次 (P1)
两个 worker 同时读取到同一待发任务：一个完成投递，另一个读取最新状态后跳过。已送达、死信、尚未到重试时间的任务不能重复发送。临时失败只按既有重试计划重新发送。
### Edge Cases
已删除仓库/任务安全跳过；业务通知创建失败时回滚；一个任务的失败不影响其他任务；多个不同仓库及接收人的任务独立处理。
## Requirements
- FR-001 同仓库同类型24小时窗口内的并发扫描仅生成一条提醒。
- FR-002 同一投递任务并发处理仅产生一次发送尝试及对应外发记录。
- FR-003 保留原提醒条件、接收人、模板与正常重试语义。
- FR-004 通知生成失败时回滚，可重试；任务缺失或状态已变化时安全跳过。
- FR-005 保留历史记录，不发送测试消息给真实用户。
### Key Entities
仓库、站内通知、接收人投递任务、外发日志。
## Success Criteria
- SC-001 两个并发扫描在重叠执行时生成总数为1。
- SC-002 两个并发 worker 针对同一任务发送总数为1。
- SC-003 重试时间未到发送数为0，到期后可再次执行且同轮仅1次。
- SC-004 已有关仓/到期与接收人回归测试通过。
## Assumptions
本次为并发重复缺陷修复；不承诺外部发送成功后进程崩溃这一跨系统不确定窗口的 exactly-once。未知实例身份作为后续运维线索，不靠停实例替代修复。
