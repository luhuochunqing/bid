# Feature Specification: 历史案例原文直接下载

**Feature Branch**: `058-historical-case-obs-download`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "案例库中历史切片案例点击'标书原文'直接下载原版标书文档，按数据来源分流：历史案例走对象存储直链、系统生成案例保留档案打包、无原文案例明确提示"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 历史案例一键下载原版标书 (Priority: P1)

投标编制人员在案例库中检索到一条来自历史投标项目的应答案例，希望拿到该案例对应的原版完整标书（Word 文档），以便复制、改写其中的应答内容用于当前投标。点击案例卡片上的"标书原文"，浏览器直接下载原版文档，文件名即原标书文件名。

**Why this priority**: 这是本特性的核心价值——消除历史案例"看得到片段、拿不到原文"的断点。历史案例是案例库冷启动的主要素材来源（300+ 条已入库），原文可得性直接决定素材复用率。

**Independent Test**: 在案例库选中任一历史切片案例，点击"标书原文"，验证浏览器下载的文档可正常打开、内容与案例片段所属原标书一致。

**Acceptance Scenarios**:

1. **Given** 案例库中存在一条历史切片案例（带有原版文档来源记录）, **When** 用户点击"标书原文", **Then** 浏览器开始下载该案例的原版标书文档，文件名与原标书名一致
2. **Given** 用户已下载一份原文, **When** 用常规文档工具打开, **Then** 文档完整可用（非空文件、非损坏包、非占位说明文本）

---

### User Story 2 - 系统生成案例保留档案打包下载 (Priority: P1)

编制人员查看由系统结项沉淀生成的案例（来源于真实项目，项目档案内有完整附件），点击"标书原文"仍然得到该项目的档案文件包（ZIP），行为与本特性上线前完全一致。

**Why this priority**: 系统案例是案例库的长期正式数据来源，其下载体验不得因本特性回归；与 Story 1 同为 P1，构成分流的两条主路径。

**Independent Test**: 选中任一系统沉淀案例（项目档案有附件），点击"标书原文"，验证下载的 ZIP 可解压且含项目真实附件。

**Acceptance Scenarios**:

1. **Given** 一条系统生成案例且其来源项目档案有附件, **When** 用户点击"标书原文", **Then** 下载该项目的档案文件包（ZIP），可正常解压
2. **Given** 一条系统生成案例且其来源项目档案无附件, **When** 用户点击"标书原文", **Then** 系统明确提示"标书原文未归档"，不产生任何下载文件

---

### User Story 3 - 无原文案例的明确反馈 (Priority: P2)

当某条案例既无原版文档来源记录、也无关联项目档案时，用户点击"标书原文"得到清晰的不可用提示，而不是静默失败或下载到空文件。

**Why this priority**: 防御性体验，防止用户拿到"看似成功实则无内容"的结果，但不承载核心价值。

**Independent Test**: 构造一条无原文来源的案例，点击"标书原文"，验证出现明确提示文案且无文件落盘。

**Acceptance Scenarios**:

1. **Given** 一条既无原版文档记录也无项目档案的案例, **When** 用户点击"标书原文", **Then** 系统提示"标书原文暂不可用"，无文件下载

---

### Edge Cases

- 原版文档来源记录存在，但对象存储中该文件已被移动/删除：下载失败时给出明确错误提示，不落盘损坏文件
- 下载授权链接有时效性：链接过期后重新点击按钮应能重新获取有效链接
- 历史案例的文档文件名含中文、空格、括号等特殊字符：下载文件名保持原名不乱码
- 同一用户连续快速点击多个案例的"标书原文"：每次独立处理，互不干扰

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 案例库中每条案例必须携带"原文来源"标记：原版文档来源记录、关联项目、或两者皆无
- **FR-002**: 系统必须根据案例的原文来源自动选择下载方式，用户面对统一的"标书原文"入口，无需感知内部分流
- **FR-003**: 对带原版文档来源记录的历史案例，系统必须生成有时效限制的临时授权下载链接并直接下载原版文档
- **FR-004**: 临时授权链接必须具备有效期（分钟级），过期后不可再访问；不得存在长期有效的公开文档链接
- **FR-005**: 下载授权的签发必须仅针对系统内已登记的文档来源记录，禁止接受外部传入的任意文件路径
- **FR-006**: 对系统生成案例，系统必须保持现有档案文件包下载行为不变
- **FR-007**: 下载的文件名必须与原始文档名一致（含中文字符）
- **FR-008**: 历史案例数据入库时必须同时写入其原版文档的来源位置记录
- **FR-009**: 任何下载失败（链接失效、对象缺失、网络错误）必须向用户呈现可读的失败原因，不得落盘无效文件

### Key Entities

- **案例（Case）**: 案例库中的一条应答素材，关键属性：来源类型（历史切片/系统沉淀）、来源项目名称、应答正文、原文来源记录
- **原文来源记录（Original Document Reference）**: 案例对应原版文档在对象存储中的定位信息，关键属性：存储位置路径、文档名；仅由数据导入管道写入，前台只读
- **临时授权链接（Temporary Authorized Link）**: 由系统按原文来源记录即时签发的短时下载凭据，关键属性：有效期、目标文档

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从点击"标书原文"到浏览器开始下载，等待时间在 5 秒以内（文档 100MB 以内）
- **SC-002**: 测试环境全量历史案例（300 条）100% 可通过"标书原文"下载到可打开的原版文档
- **SC-003**: 系统生成案例的档案打包下载行为 0 回归（与本特性上线前一致）
- **SC-004**: 无原文案例点击后 100% 得到明确提示，0 次产生空文件/损坏文件下载
- **SC-005**: 不存在任何超过有效期仍可访问的文档公开链接

## Assumptions

- 对象存储桶的访问凭证与现有系统凭证一致且已被验证具备读取与签发权限（2026-09-01 实测通过）
- 历史案例的原版文档（投标文件）在对象存储中 70/70 项目齐全；招标文件匹配不在本期范围
- 案例库访问权限模型不变：能查看案例的用户即可下载其原文，不新增项目级权限校验（历史案例无项目归属）
- 现有档案文件包下载链路（系统案例）保持不动，含其已知修复的随版生效
- 浏览器直接触发下载即可，不做浏览器内在线预览
