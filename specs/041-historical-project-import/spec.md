# Feature Specification: 历史投标项目信息批量导入

**Feature Branch**: `agent/claude/historical-project-import`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "我想完善历史项目信息，我做了一个采集表来收集历史的项目信息，把这个表导入到数据库。需要确保各个项目页面都不报错，项目详情和项目列表会有联动，如果有一些数据丢失会不会报错。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员批量导入历史项目（Priority: P1）

投标管理员拿到一份 Excel 采集表（19 列，包含项目名称、招标主体、来源平台、状态、客户类型、优先级、开标时间、联系人、项目负责人、投标负责人、服务周期等），需要将表中所有历史项目一次性导入到系统。导入完成后，每个历史项目在项目列表页和项目详情页都能完整显示，不出现字段空白或页面报错。

**Why this priority**: 这是本功能的核心价值——让历史项目数据完整落库并在前端正常展示。没有这个能力，采集表就只是一张离线表格，无法产生业务价值。

**Independent Test**: 导入一份含 5 条历史项目的测试采集表，登录管理员账号打开项目列表页，确认 5 条项目全部出现且 19 个字段（项目名称/招标主体/来源平台/状态/总部所在地/客户类型/项目类型/优先级/客户营收/计划入围供应商数/开标时间/投标月份/联系人/项目负责人/投标负责人/服务周期/服务周期截止时间/项目阶段）都有值；逐条打开详情页，确认基本信息、标讯联系人、阶段时间轴等模块均正常加载。

**Acceptance Scenarios**:

1. **Given** 管理员已登录且持有一份填写完整的采集表（5 条历史项目，状态均为"已中标/未中标/已流标/已放弃"之一），**When** 管理员上传采集表并触发导入，**Then** 系统在 1 分钟内完成全部 5 条项目导入，返回"成功 5 条，失败 0 条"的汇总结果，且每条项目在列表页和详情页都能完整显示所有字段。
2. **Given** 采集表中某行的"投标负责人"工号在用户表中不存在，**When** 管理员触发导入，**Then** 该行被跳过并记录到失败清单（含行号、项目名称、失败原因"投标负责人工号 XXX 未找到对应用户"），其余行正常导入，导入结束后展示失败清单供管理员修正后重导。
3. **Given** 采集表中某行的必填字段（如项目名称、招标主体、状态、项目负责人、投标负责人、服务周期、服务周期截止时间）为空，**When** 管理员触发导入，**Then** 该行被跳过并记录到失败清单，失败原因明确指出哪个必填字段缺失。

---

### User Story 2 - 导入后项目列表页字段完整显示（Priority: P2）

管理员导入历史项目后，打开项目列表页，看到这些历史项目和正常新建的项目一样，列表的所有列都有值显示（包括优先级、客户营收、计划入围供应商数、投标月份、项目负责人姓名、投标负责人姓名、服务周期、服务周期截止时间等扩展字段），不会出现大面积空白或"-"。

**Why this priority**: 列表页是用户查看项目的第一入口。如果导入的历史项目在列表页大量字段空白，用户会质疑数据完整性，影响信任度。

**Independent Test**: 导入含 3 条历史项目的采集表（优先级/客户营收/入围供应商数/服务周期等字段均填写），打开项目列表页，确认这 3 条记录的扩展字段（优先级、客户营收、计划入围供应商数、投标月份、项目负责人、投标负责人、服务周期、服务周期截止时间）全部有值，不显示空白或"-"。

**Acceptance Scenarios**:

1. **Given** 已导入 3 条历史项目且采集表填写完整，**When** 管理员打开项目列表页，**Then** 3 条记录的"优先级"列分别显示 S/A/B 等值，"客户营收(亿)"列显示数值，"计划入围供应商数"列显示数字，"投标月份"列显示 yyyy-MM 格式，"项目负责人"列显示"姓名 (工号)"格式，"投标负责人"列显示"姓名 (工号)"格式，"服务周期(年)"列显示数值，"服务周期截止时间"列显示日期。
2. **Given** 已导入历史项目，**When** 管理员按"优先级=S"筛选列表，**Then** 筛选结果正确返回优先级为 S 的历史项目，证明扩展字段已正确落库并可查询。

---

### User Story 3 - 导入后项目详情页联动数据正常加载（Priority: P3）

管理员导入历史项目后，点击任意一条进入项目详情页，基本信息卡显示完整（招标主体、来源平台、客户类型、优先级、开标时间等），标讯联系人模块显示采集表填写的联系人姓名和电话，阶段时间轴显示"已结项"状态，不出现"关联标讯已被删除"等错误提示。

**Why this priority**: 详情页是用户深度查看项目的页面，联动数据的完整性直接影响用户对历史项目信息的可信度。

**Independent Test**: 导入 1 条含联系人信息的采集表，打开该项目详情页，确认"基本信息"卡所有字段有值，标讯联系人模块显示采集表填写的联系人姓名和电话（不是"暂无"），阶段时间轴显示"已结项"。

**Acceptance Scenarios**:

1. **Given** 已导入 1 条历史项目，采集表填写了联系人姓名"张三"和电话"13800138000"，**When** 管理员打开该项目详情页，**Then** 基本信息卡显示招标主体、来源平台、客户类型、优先级、开标时间等字段值，标讯联系人模块显示"张三 / 13800138000"。
2. **Given** 已导入 1 条历史项目，状态为"已中标"，**When** 管理员打开详情页，**Then** 阶段时间轴显示"已结项"阶段，且"结果确认"相关字段（服务周期、服务周期截止时间）有值显示。

---

### Edge Cases

- **采集表行数超过 1000 行**：批量导入如何处理？是否需要分批？是否需要异步导入 + 进度反馈？
- **采集表中有重复项目名称**：如何处理？跳过、覆盖、还是报错？是否需要去重校验？
- **"投标负责人"和"项目负责人"是同一个人**：是否允许？project_lead_assignment 和 projects.manager_id 如何关联？
- **采集表的"开标时间"格式不规范**（如只有日期没有时间、或文本格式"2025年6月20日"）：如何解析？
- **采集表的"客户营收"为 0 或负数**：是否允许？annual_revenue 字段是否接受 0/负值？
- **导入过程中发生异常**（如数据库连接中断）：已导入的记录是否回滚？是否支持断点续传？
- **历史项目的占位标讯是否需要在标讯列表页显示**？如果显示，如何区分占位标讯和真实标讯？是否需要过滤？
- **重复导入同一份采集表**：是否支持幂等？第二次导入会创建重复项目还是跳过？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持通过 Excel 采集表（19 列）批量导入历史投标项目，每行对应一个历史项目。
- **FR-002**: 系统 MUST 在导入时为每个历史项目创建以下关联数据，确保列表页和详情页字段完整：
  - 一条占位标讯记录（承载优先级、联系人、开标时间、招标主体等标讯侧字段）
  - 一条项目立项详情记录（承载计划入围供应商数、客户营收、投标月份等立项阶段字段）
  - 一条项目结果记录（承载服务周期年、服务周期截止时间等结果确认字段，仅当状态为终态时创建）
  - 一条项目负责人指派记录（关联项目负责人用户）
- **FR-003**: 系统 MUST 在导入时解析"姓名（工号）"格式的项目负责人和投标负责人，按工号查找对应用户，将用户 ID 写入项目的负责人字段和项目负责人指派记录。
- **FR-004**: 系统 MUST 仅接受 4 个终态项目状态：已中标、未中标、已流标、已放弃。采集表中出现其他状态值（如投标中、评标中）时，该行记为失败。
- **FR-005**: 系统 MUST 在导入终态状态项目时，将项目阶段设为"已结项"，满足"终态状态要求阶段为已结项"的业务约束。
- **FR-006**: 系统 MUST 在导入时将"客户营收(亿)"转换为元存储（采集表单位为亿，数据库存储单位为元）。
- **FR-007**: 系统 MUST 对采集表的必填字段（项目名称、招标主体、来源平台、状态、总部所在地、客户类型、项目类型、优先级、开标时间、项目负责人、投标负责人、服务周期、服务周期截止时间、项目阶段）进行非空校验，缺失必填字段的行记为失败并跳过。
- **FR-008**: 系统 MUST 在导入结束后返回汇总结果，包含：成功条数、失败条数、失败明细清单（行号、项目名称、失败原因）。
- **FR-009**: 系统 MUST 对工号在用户表中不存在的行记为失败并跳过，失败原因明确指出"投标负责人工号 XXX 未找到对应用户"或"项目负责人工号 XXX 未找到对应用户"。
- **FR-010**: 系统 MUST 在导入完成后触发档案归档流程，为每个成功导入的历史项目创建档案记录。
- **FR-011**: 系统 MUST 将占位标讯标记为"历史项目导入"来源（通过 external_id 前缀或 source 字段标识），便于后续区分真实标讯和占位标讯。
- **FR-012**: 系统 MUST 支持采集表多行导入（至少支持 500 行），单次导入超时不超过 5 分钟。

### Key Entities *(include if feature involves data)*

- **历史项目采集表**: Excel 格式，19 列，每行一个历史项目。包含项目基本信息（名称/状态/阶段）、招标信息（招标主体/来源平台/客户类型/优先级）、时间信息（开标时间/投标月份/服务周期）、人员信息（联系人/项目负责人/投标负责人）、财务信息（客户营收/计划入围供应商数）。
- **项目（Project）**: 系统核心实体，承载项目名称、状态、阶段、经理、招标主体、来源平台、客户类型、地区、行业、预算、截止日期、服务周期截止时间等。
- **占位标讯（Tender）**: 为历史项目创建的关联标讯，承载优先级、联系人、开标时间、招标主体、客户类型等标讯侧字段。标记为"历史项目导入"来源。
- **项目立项详情（ProjectInitiationDetails）**: 承载计划入围供应商数、客户营收（年营收）、投标月份、客户类型等立项阶段补充字段。
- **项目结果（ProjectResult）**: 承载服务周期年、服务周期截止时间、中标金额等结果确认字段。仅终态项目创建。
- **项目负责人指派（ProjectLeadAssignment）**: 关联项目负责人与项目，记录主负责人用户 ID。
- **用户（User）**: 通过工号（employee_number）关联采集表的"项目负责人"和"投标负责人"。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员能在 5 分钟内完成一份 100 行历史项目采集表的导入，并收到明确的成功/失败汇总。
- **SC-002**: 导入成功的历史项目，在项目列表页 19 个字段全部有值显示，不出现空白或"-"（采集表未填的可选字段除外）。
- **SC-003**: 导入成功的历史项目，在项目详情页基本信息卡、标讯联系人模块、阶段时间轴均正常加载，不出现"关联标讯已被删除"等错误提示。
- **SC-004**: 导入失败的历史项目，失败原因能精确定位到具体行号和具体字段（如"第 15 行：投标负责人工号 999999 未找到对应用户"），管理员能据此修正采集表后重新导入。
- **SC-005**: 导入后的历史项目支持按优先级、客户类型、状态等字段筛选和查询，筛选结果正确。
- **SC-006**: 同一份采集表重复导入时，系统能识别已存在的项目并跳过或提示，不会创建重复项目记录。

## Assumptions

- 采集表由投标管理员线下收集并填写，格式为 Excel（.xlsx），列顺序和列名遵循模板定义的 19 列。
- 采集表的"项目负责人"和"投标负责人"字段格式为"姓名（工号）"，工号对应系统用户表的 employee_number 字段，且该用户存在。
- 历史项目导入仅支持 4 个终态状态（已中标/未中标/已流标/已放弃），不支持进行中状态（投标中/评标中），因为历史项目均已结束。
- 历史项目的项目阶段统一为"已结项"，不需要支持其他阶段。
- 客户营收单位为亿（采集表填写 10.5 表示 10.5 亿元），数据库存储单位为元，导入时自动转换。
- 占位标讯仅在项目详情页联动加载，不在标讯列表页主动展示（避免污染真实标讯数据）。
- 导入操作仅限管理员角色，非管理员无权限。
- 现有 ProjectImportService 的 importProject 方法已存在但字段覆盖不全，本功能在其基础上扩展，不破坏现有 API 契约。
