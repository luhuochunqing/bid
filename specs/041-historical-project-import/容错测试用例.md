## 容错策略回顾（spec 已确认）

| 场景 | 行为 | 影响 |
|---|---|---|
| 必填字段缺失 | **跳过该行** + 记入失败清单 | 不影响其他行 |
| 工号不存在 | **跳过该行** + 记入失败清单 | 不影响其他行 |
| 状态非法 | **跳过该行** + 记入失败清单 | 不影响其他行 |
| 重复导入（external_id 匹配） | **跳过该行** + 记入"已存在跳过"清单 | 不创建重复记录 |
| 可选字段为空 | **正常导入**（可选字段写入 NULL） | 不报错 |
| 单行异常（数据库异常等） | **该行事务回滚** + 记入失败清单 | 已成功行不回滚 |

**核心原则**：单行数据问题**绝不**中断整个导入流程。每行独立事务（`@Transactional(propagation = REQUIRES_NEW)`），失败行回滚，成功行提交。

| 工号 | 数据库 id | 系统姓名 | 用途 |

数据库现状：dev 测试用户（`bid_admin` / `bid_lead` / `sales` / `bid_specialist` / `admin_staff`）和 e2e 测试用户（`lizong` / `xiaowang` / `xiaochen` 等）**全部没有 `employee_number`**。

## 验证步骤（导入逻辑实现后执行）

### 步骤 1：上传测试 Excel

```bash
# 登录 admin 获取 token

  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"XiyuAdmin2026!"}' | jq -r '.data.token')

curl -s -X POST http://127.0.0.1:18089/api/projects/import/historical \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@specs/041-historical-project-import/历史项目导入测试数据.xlsx" | jq
```

### 步骤 2：验证后端返回的汇总结果

确认返回：
- `successCount: 2`
- `failureCount: 3`
- `failures` 数组包含 3 条失败明细，行号分别为 3/4/5
- 失败原因精确指出具体字段和原因

### 步骤 3：验证数据库写入

```sql
-- 查询导入成功的 2 个项目
SELECT id, name, status, stage, manager_id, customer, platform
FROM projects
WHERE name LIKE '测试项目-正常完整数据' OR name LIKE '测试项目-可选字段为空';

-- 查询占位标讯
SELECT id, title, external_id, source, status
FROM tenders
WHERE external_id LIKE 'HISTORICAL_%';

-- 验证占位标讯不在标讯列表（external_id NOT LIKE 'HISTORICAL_%' 过滤生效）
SELECT COUNT(*) FROM tenders WHERE external_id NOT LIKE 'HISTORICAL_%' AND external_id LIKE 'HISTORICAL_%';
-- 期望 0（即 HISTORICAL_ 前缀的全部被过滤）

-- 验证立项详情
SELECT pid.project_id, pid.expected_bidders, pid.annual_revenue, pid.bid_month
FROM project_initiation_details pid
JOIN projects p ON pid.project_id = p.id
WHERE p.name LIKE '测试项目-%';

-- 验证项目结果（仅终态项目）
SELECT pr.project_id, pr.result_type, pr.service_period_years, pr.service_period_end_date
FROM project_result pr
JOIN projects p ON pr.project_id = p.id
WHERE p.name LIKE '测试项目-%';

-- 验证项目负责人指派
SELECT pla.project_id, pla.primary_lead_user_id
FROM project_lead_assignment pla
JOIN projects p ON pla.project_id = p.id
WHERE p.name LIKE '测试项目-%';
```

### 步骤 4：验证前端列表页

1. 登录 admin 打开项目列表页
2. 确认"测试项目-正常完整数据"和"测试项目-可选字段为空"两条项目出现
3. 确认扩展字段（优先级/客户营收/服务周期等）有值显示
4. 确认按"优先级=S"筛选能找到"测试项目-正常完整数据"

### 步骤 5：验证前端详情页

1. 点击"测试项目-正常完整数据"进入详情页
2. 确认基本信息卡完整（招标主体/来源平台/客户类型/优先级/开标时间）
3. 确认标讯联系人模块显示"张三 / 13800138000"
4. 确认阶段时间轴显示"已结项"

## 边界场景补充测试（手动构造）

以下场景不在测试 Excel 中，可手动修改 Excel 验证：

| 场景 | 构造方式 | 预期 |
|---|---|---|
| 501 行超限 | 复制行 2 到第 501 行 | 返回 400「单次导入上限 500 行」 |
| 上传 .csv 文件 | 把 .xlsx 另存为 .csv | 返回 400「请上传 .xlsx 格式的采集表」 |
| 上传空文件 | 创建空 .xlsx | 返回 400「文件为空」 |
| 开标时间文本格式"2025年6月20日" | 把 K 列改成文本 | 解析成功（多格式支持） |
| 客户营收为 0 | I 列填 0 | 成功导入（0 是合法值） |
| 客户营收为负数 | I 列填 -1 | 失败跳过（annual_revenue 不允许负值） |
| 项目负责人和投标负责人同一人 | O 列和 P 列填相同工号 | 成功导入（允许一人多职） |
| 全角括号 vs 半角括号 | O 列用「（）」全角 | 都能正确解析工号 |
