# Feature Specification: AI 案例切片语义检索

**Feature Branch**: `agent/claude/ai-case-slice-semantic-search`

**Created**: 2026-07-04

**Status**: Draft

**Input**: User description: "基于服务器上 70 个历史投标文件的章节切片，构建语义检索能力。当用户在标书制作阶段查看某个评分项时，系统能够根据评分项标题和评分规则，从历史投标文件章节切片中推荐语义最相似的应答片段，作为编写当前标书的参考素材。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 评分项智能推荐相似应答 (Priority: P1)

投标专员在标书制作阶段打开一个项目，系统已经解析出招标文件中的评分项。当专员点击"AI智能案例推荐"时，系统根据当前评分项的标题和评分规则，从历史投标文件切片中找出语义最相近的 20 个章节片段，帮助专员快速找到可参考的应答内容。

**Why this priority**: 这是用户提出的核心需求，直接解决"历史投标文件沉睡、无法复用"的痛点，能立刻提升标书撰写效率。

**Independent Test**: 选择一个真实评分项（如"技术方案"），调用推荐接口，验证返回结果中包含历史项目中语义相关的章节标题和正文预览。

**Acceptance Scenarios**:

1. **Given** 系统已导入历史投标文件切片，**When** 用户选择一个评分项并请求推荐，**Then** 系统在 3 秒内返回最多 20 个按相关度排序的应答片段。
2. **Given** 用户选择的评分项为"物流技术与系统优势"，**When** 系统执行推荐，**Then** 返回结果中优先出现包含"物流系统""仓储管理""配送方案"等语义相关的历史切片，而不是仅标题字面包含"物流"的切片。
3. **Given** 历史切片中存在标题语义相似但正文过短或属于非应答章节的内容，**When** 系统执行推荐，**Then** 这些低价值切片不会出现在 Top-20 结果中。

---

### User Story 2 - 历史切片批量入库与向量化 (Priority: P1)

系统把服务器上 70 个项目中已抽取的 8144 个投标文件章节切片导入数据库，并为每个切片生成语义向量。这些向量为后续"评分项→应答片段"推荐提供检索基础。

**Why this priority**: 没有入库和向量化，推荐功能就无法工作，是 P1 用户故事的前置条件。

**Independent Test**: 检查数据库中是否成功写入 8144 条切片记录，且大部分记录已生成非空的 embedding 字段。

**Acceptance Scenarios**:

1. **Given** 切片元数据文件已就绪，**When** 管理员执行导入命令，**Then** 系统在 10 分钟内完成 8144 条切片元数据入库。
2. **Given** 切片已入库但尚未生成向量，**When** 系统启动批量向量化任务，**Then** 每条切片在调用一次 embedding 服务后获得对应的向量表示，失败记录可被重试或跳过。
3. **Given** 向量化任务执行过程中出现异常，**When** 异常恢复后，**Then** 系统能够从断点继续处理未向量化的切片，而不是全部重做。

---

### User Story 3 - 按评分项维度触发推荐 (Priority: P2)

用户可以直接输入任意查询文本（调试、测试或未来其他场景），系统基于该文本从历史切片中返回语义相似的应答片段，无需绑定到具体项目的评分项。

**Why this priority**: 便于调试和验证语义检索质量，也为后续扩展（如全局搜索、素材库）打下基础。

**Independent Test**: 使用任意查询文本调用接口，验证返回结果的语义相关性。

**Acceptance Scenarios**:

1. **Given** 用户输入查询"售后服务保障措施"，**When** 调用开放查询接口，**Then** 返回结果中包含"售后""质保""服务承诺"等语义相关的切片。
2. **Given** 用户未提供查询文本，**When** 调用开放查询接口，**Then** 系统返回明确的输入校验提示，而不是空列表或 500 错误。

---

### Edge Cases

- 当某个历史项目只有非应答章节（如资质证书、营业执照）时，这些切片在预处理阶段已被过滤，不会进入推荐候选池。
- 当 embedding 服务暂时不可用时，系统应返回降级提示，而不是卡住或返回随机结果。
- 当某个评分项的查询文本非常短（如"技术"）或非常长（超过 3000 字）时，系统应做长度截断或提示用户补充信息。
- 当数据库中尚无切片或全部切片未向量化时，推荐接口应返回空列表并附带原因说明。
- 当多个切片来自同一个项目时，系统应对同一项目的返回数量做限制，避免推荐结果被单一项目垄断。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持将历史投标文件章节切片（约 8144 条）批量导入独立存储，切片元数据至少包含项目目录、文件路径、章节标题、正文预览、段落数、章节层级、文件类别。
- **FR-002**: 系统 MUST 支持为每个切片生成语义向量，向量模型可配置切换，默认使用通义千问 text-embedding-v3（1024 维）。
- **FR-003**: 系统 MUST 提供一个推荐接口，接收评分项 ID（或查询文本），返回按语义相关度排序的最多 20 个历史应答切片。
- **FR-004**: 推荐结果 MUST 包含切片 ID、来源项目、文件类别、章节标题、正文预览、相似度分数和匹配理由。
- **FR-005**: 系统 MUST 在召回阶段使用向量相似度快速缩小候选范围，在精排阶段结合标题匹配、文件类别、正文充实度、章节层级等业务规则进行综合打分。
- **FR-006**: 系统 MUST 对输入文本做长度限制与截断，避免超出 embedding 模型的上下文窗口。
- **FR-007**: 批量向量化任务 MUST 支持断点续跑、失败重试和限速，避免一次性压垮 embedding 服务。
- **FR-008**: 推荐接口 MUST 复用现有项目权限校验，只有能访问当前项目的用户才能查看推荐结果。

### Key Entities

- **BidCaseSlice（案例切片）**: 历史投标文件中的章节片段。关键属性包括来源项目目录、文件路径、文件类别、章节标题、正文预览、段落数、章节层级、语义向量、向量化模型。
- **ProjectScoreDraft（评分项草稿）**: 从当前项目招标文件解析出的评分项。关键属性包括评分项标题、评分规则原文、类别、分值。本功能主要消费其标题和规则原文作为查询输入。
- **CaseSliceRecommendation（切片推荐结果）**: 返回给用户的一条推荐。关键属性包括切片标识、来源项目、章节标题、正文预览、相似度分数、匹配理由。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 系统能够在 5 秒内为任意有效评分项返回 Top-20 推荐结果（在向量化完成的前提下）。
- **SC-002**: 返回的 Top-20 结果中，至少 80% 的切片在语义上与查询评分项相关（可通过人工抽检 30 条评分项验证）。
- **SC-003**: 8144 条切片中至少 90% 成功生成向量并入库。
- **SC-004**: 当 embedding 服务不可用时，推荐接口在 2 秒内返回可理解的降级提示，而不是超时或崩溃。
- **SC-005**: 同一来源项目在单次推荐结果中占比不超过 30%，避免推荐结果过度集中。

## Assumptions

- 历史投标文件切片已经通过前置脚本完成抽取，格式为 JSONL，可直接用于批量导入。
- embedding 服务默认使用通义千问 text-embedding-v3，用户将自行购买并配置 API key。
- 历史项目的中标结果、客户类型、项目类型等字段无法补齐，本阶段不做强制要求，允许为空。
- 加密格式的招标文件和电子招标平台特殊格式文件不在本次处理范围内。
- 本功能优先服务于"相似应答片段推荐"，不强制要求与现有 `knowledge_case` 表做一对一映射。
