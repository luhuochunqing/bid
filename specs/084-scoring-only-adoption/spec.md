# Feature Specification: 评分事实与非计分审查事实分离

**Feature Branch**: `agent/codex/scoring-only-adoption`
**Created**: 2026-11-11
**Status**: Approved scope for local implementation
**Input**: 根据项目1120和44的根因制定详细修复计划和任务，然后修复。

## User Scenarios & Testing
### User Story 1 - 评分列表只采纳计分项 (Priority: P1)
用户查看和采纳评分标准时，不再将资格、形式、否决等非计分行作为正式评分项。
**Independent Test**: 同方案混合资格项、评分项与否决项，默认和显式批量采纳均只产生正分评分项及经完整原文核验的零分扣分项；总分保持100。
**Acceptance Scenarios**:
- AC01：零分或缺分的来源事实保留；复核候选不能因属于评审章节就自动可采纳。内部来源归属仍按原语义核验，以支持行覆盖。
- AC02：默认、显式ID和旧页面提交路径均不能将无可信扣分证据的零分/缺分项写入正式评分列表；混合提交跳过此类项，全无有效分值时返回明确失败。
- AC03：真实正分条款包含“资格”“否决”等引用时仍可采纳，原文、分值和父子聚合不被改变。
### User Story 2 - 未确认分值可复核且历史候选可用 (Priority: P1)
用户仍可查看所有审计事实，对真正分值未识别的评分条款人工补齐正分值后采纳。
**Independent Test**: 历史candidateEligible=true零分记录在当前快照及默认选择中不再当作计分候选；人工明确纳入并补正分值可采纳。
- AC04：前端默认候选和提交使用同一规则，非计分事实进入审计区，允许显式纳入编辑；不能自动把未知分值解释为零分评分项。
- AC05：补分后的正分候选沿用现有人工核对能力；负分依旧拒绝。方案排除、替代事实集及聚合保护保持。
### User Story 3 - 两项目历史数据可审计恢复 (Priority: P2)
提供项目1120/44的有条件恢复步骤，区分代码修复、部署、重新解析、人工采纳及实际评分重算。
**Independent Test**: runbook包含固定任务/文件校验、备份、预览、采纳后条数/零分数/总分/原文核对以及回退步骤。
- AC06：不自动删除历史事实，不迁移全库、不在GET时偷偷过滤/写入、不直接执行生产恢复。

## Requirements
FR-001：原文方案归属不能单独证明可计分，评分候选须有正分值或完整原文核验的零分扣分证据。
FR-002：人工采纳检查调整后的分值；零分/缺分不进入正式集合，除非是经完整原文核验且原文未改动的零分扣分规则，负分明确拒绝。
FR-003：原始证据完整保留，旧快照的误标记在读取映射时重新受计分条件约束；缺少可信扣分证据的历史零分不靠关键词推测放行。
FR-004：前后端规则一致；不得因字段名包含资格而删除真实正分项。
FR-005：局部修复，无新表、新模型依赖、生产数据写入或部署。

## Key Entities
解析事实：源文档证据；来源方案归属：事实属于哪个方案；候选计分项：已确认正分值或有完整原文证据的零分扣分规则，并满足现有方案边界；正式项：已采纳生效结果。

## Success Criteria
SC-001：混合回放中无证据的零分正式项数量为0，正分项、可信零分扣分项及总分全部保留。
SC-002：显式与默认采纳及旧候选路径均受约束，缺分人工补齐正分后可成功。
SC-003：原始事实数量不因本修复减少，两项目恢复步骤可逐项复核。

## Assumptions / Scope
本次0指评分标准最大分值，不是供应商实际得分；未知分值/价格公式保留作审计事实，不自动进入正式评分；既有完整原文核验的零分扣分例外保持。允许沿用现有人工明确补分；不能据此宣称原文已核验。生产项目具体正确项数需部署后与当前原件逐项核对，不能把全部零分都确认为资格项。授权仅本地修复。

## Review correction (round 1)
来源核验的candidateEligible是内部来源契约，不能直接加正分门槛，否则原文覆盖/版本化零分扣分能力回归。采纳边界需复用SourceDeductionSelectionPolicy.verified产出的服务端可信证据；原始sourceText改变或来源不完整即失效，不接受客户端自报布尔值。
