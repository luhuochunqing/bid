# Feature Specification: 修复项目详情页 403 错误与前端权限入口校验

**Feature Branch**: `026-fix-project-detail-403-frontend`

**Created**: 2026-07-03

**Status**: Draft

**Input**: User description: "用户 08687（bid-projectLeader, dataScope=self）访问项目 138 详情页报 403 错误，刷新后恢复正常。根因：前端存在多个绕过项目列表权限过滤的直接跳转入口，使用户能进入无权限项目的详情页；详情页对 403 响应静默返回 null，导致后续代码崩溃。需修复前端入口权限校验和 403 响应处理。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户从外部入口跳转无权限项目时获得友好提示 (Priority: P1)

投标项目负责人（bid-projectLeader, dataScope=self）在标讯详情页点击"查看投标项目"按钮，或在工作台/分析看板/保证金管理等页面点击项目卡片时，如果该项目不在其数据权限范围内（不是其负责或参与的项目），系统应在跳转前或跳转后给出明确的"无权限访问该项目"提示，并阻止进入项目详情页或将其引导回来源页/项目列表页，而不是让用户进入一个加载失败、控制台报错的破图页面。

**Why this priority**: 这是本次 Bug 的核心症状。当前行为是用户能看到跳转按钮、能进入详情页 URL、然后页面崩溃报 403 和 TypeError，体验极差且暴露后端权限模型。修复此问题直接解决用户报告的生产 Bug。

**Independent Test**: 以一个 bid-projectLeader 账号登录，通过标讯详情页的"查看投标项目"按钮尝试跳转到其无权限的项目（project_id 不在其可访问范围），验证是否出现友好提示且不进入崩溃页面。

**Acceptance Scenarios**:

1. **Given** 用户已登录且角色为 bid-projectLeader（dataScope=self），**When** 用户在标讯详情页点击"查看投标项目"按钮跳转到一个其无权限的项目（该项目的 projectId 不在其可访问项目集合中），**Then** 系统显示"无权限访问该项目"的提示消息，不进入项目详情页或将其引导回标讯详情页/项目列表页，浏览器控制台不报 403 错误和 TypeError
2. **Given** 用户已登录且角色为 bid-projectLeader（dataScope=self），**When** 用户在工作台点击"我的项目"卡片列表中某个无权限项目的卡片（理论上工作台不应展示无权限项目，但作为防御性处理），**Then** 系统显示"无权限访问该项目"提示，不进入崩溃页面
3. **Given** 用户已登录且角色为 bid-projectLeader（dataScope=self），**When** 用户在分析看板下钻、保证金管理跳转、日程事件点击等任一入口尝试访问无权限项目，**Then** 系统统一显示"无权限访问该项目"提示，行为一致
4. **Given** 用户已登录且有权限访问该项目，**When** 用户从任一入口跳转到该项目详情页，**Then** 正常进入项目详情页，无任何提示和错误

---

### User Story 2 - 项目详情页对加载失败场景优雅降级 (Priority: P1)

当项目详情页因为任何原因（403 无权限、404 项目不存在、网络错误、后端服务异常）无法加载到项目数据时，详情页应展示一个明确的错误状态界面（如"项目不存在或无权限访问"），提供"返回项目列表"按钮，而不是显示空白页面、骨架屏卡死、或控制台报 TypeError。

**Why this priority**: 这是 Bug 的第二层症状——即使前端入口未做校验，详情页本身对 403 的处理也应优雅降级，而不是让 `currentProject = null` 后续代码崩溃。这是防御性编程的基本要求，与 User Story 1 互为兜底。

**Independent Test**: 直接在浏览器地址栏输入一个无权限的项目 URL（如 `/project/138`），验证详情页展示错误状态界面而非崩溃。

**Acceptance Scenarios**:

1. **Given** 用户已登录但无权限访问项目 138，**When** 用户直接在地址栏输入 `/project/138` 并回车，**Then** 项目详情页展示"无权限访问该项目"或"项目不存在"的错误状态界面，提供"返回项目列表"按钮，控制台不报 TypeError
2. **Given** 用户已登录，**When** 用户访问一个不存在的项目 URL（如 `/project/999999`），**Then** 项目详情页展示"项目不存在"错误状态界面，提供"返回项目列表"按钮
3. **Given** 用户已登录且有权限，**When** 后端服务暂时不可用导致项目详情接口返回 500，**Then** 项目详情页展示"加载失败，请重试"错误状态，提供"重试"和"返回项目列表"按钮

---

### User Story 3 - 统一项目跳转入口的权限校验机制 (Priority: P2)

所有跳转到项目详情页的入口（标讯详情页、工作台、分析看板、保证金管理、日程事件、二次招标等）应使用统一的跳转工具函数，该函数在跳转前或跳转后统一处理权限校验和 403 响应，避免每个入口各自实现导致行为不一致。

**Why this priority**: 这是根本性修复，防止未来新增跳转入口时再次遗漏权限校验。User Story 1 和 2 是即时修复，User Story 3 是架构治理。

**Independent Test**: 全局搜索所有 `router.push` 跳转到 ProjectDetail 的代码，验证均通过统一的工具函数调用，不存在裸 `router.push({ name: 'ProjectDetail', ... })` 或裸 `router.push('/project/:id')` 调用。

**Acceptance Scenarios**:

1. **Given** 开发者新增一个跳转到项目详情页的入口，**When** 代码审查时检查跳转代码，**Then** 该入口必须调用统一的项目跳转工具函数，不直接使用 `router.push` 跳转 ProjectDetail
2. **Given** 所有现有跳转入口已迁移到统一工具函数，**When** 用户从任一入口跳转无权限项目，**Then** 行为完全一致（同样的提示文案、同样的回退行为）

---

### Edge Cases

- **用户在跳转过程中权限被撤销**：用户点击跳转按钮的瞬间有权限，但请求到达后端时权限被管理员撤销（如被移出项目成员），后端返回 403。详情页应优雅处理此场景，展示错误状态而非崩溃。
- **用户在标讯详情页点击"查看投标项目"但标讯未关联项目**：`tender.projectId` 为 null 或 undefined，跳转按钮应禁用或点击后提示"该标讯未关联项目"。
- **项目 ID 格式异常**：URL 中输入 `/project/abc`（非数字），应在路由层或详情页层拦截，提示"项目 ID 无效"。
- **用户从通知中心/小铃铛跳转到项目详情**：通知中携带 projectId，用户点击后跳转，若该项目已无权限（如任务被转派），应展示友好提示。
- **网络瞬时抖动导致 403**：极少数情况下网络重试可能导致 403，但更常见的是真正的权限不足。不应自动重试 403，而应直接展示错误状态（避免误导用户）。
- **结项阶段二次招标创建新项目后跳转**：新创建的项目当前用户必然有权限（作为项目负责人），此场景不应被权限校验拦截，但仍应走统一入口以保证一致性。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在所有跳转到项目详情页的入口（标讯详情页、工作台、分析看板、保证金管理、日程事件、二次招标等）实施统一的权限校验或统一的 403 响应处理
- **FR-002**: 系统 MUST 在用户尝试访问无权限项目时显示明确的"无权限访问该项目"提示消息，而非静默失败或显示空白崩溃页面
- **FR-003**: 系统 MUST 在项目详情页无法加载项目数据时（403/404/网络错误）展示错误状态界面，并提供"返回项目列表"导航按钮
- **FR-004**: 系统 MUST NOT 在项目详情页加载失败时抛出未捕获的 JavaScript 错误（如 TypeError: Cannot read properties of null）
- **FR-005**: 项目详情页加载逻辑 MUST 在 `currentProject` 为 null 时提前终止后续依赖 `currentProject` 属性的操作（如访问 `currentProject.id`）
- **FR-006**: 系统 MUST 提供统一的项目跳转工具函数，所有跳转到 ProjectDetail 的入口 MUST 通过该函数调用，不得直接使用 `router.push({ name: 'ProjectDetail' })` 或 `router.push('/project/:id')`
- **FR-007**: 统一跳转工具函数跳转后，项目详情页 MUST 捕获 403 响应并展示"无权限访问该项目"提示，详情页提供"返回项目列表"导航（入口侧不预处理权限，由详情页统一处理，避免额外 API 请求）
- **FR-008**: 系统 MUST 保留用户对有权限项目的正常跳转体验，权限校验和 403 处理不得影响正常流程的性能和体验
- **FR-009**: 系统 MUST 在标讯详情页"查看投标项目"按钮点击时，若 `tender.projectId` 为空，提示"该标讯未关联项目"而非跳转到无效 URL
- **FR-010**: 系统 MUST 区分 403（无权限）和 404（不存在）两种错误状态，展示不同的提示文案（"无权限访问该项目" vs "项目不存在"）
- **FR-011**: 错误状态界面 MUST 提供"返回项目列表"按钮，点击后跳转到 `/project` 路由
- **FR-012**: 系统 MUST NOT 自动重试 403 响应（避免误导用户以为是瞬时错误）

### Key Entities *(include if feature involves data)*

- **项目访问权限**：用户对项目的访问权限由后端 `ProjectAccessScopeService` 计算，聚合 9 条权限路径（负责人、团队成员、显式授权、项目组、项目成员、主负责人、立项人、任务执行人、部门范围）。前端无需感知权限计算逻辑，只需处理后端返回的 403/404 响应。
- **项目跳转入口**：所有可能跳转到项目详情页的页面或组件，包括标讯详情页、工作台、分析看板、保证金管理、日程事件、二次招标等。每个入口携带一个 `projectId` 参数。
- **项目详情页状态**：项目详情页的加载状态，包括 loading（加载中）、success（加载成功）、no-permission（无权限）、not-found（不存在）、error（其他错误）。当前实现只有 loading 和隐式的 null（崩溃）状态，需补充明确的错误状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: bid-projectLeader 角色用户从任意外部入口（标讯详情页、工作台、分析看板等）尝试访问无权限项目时，100% 会看到"无权限访问该项目"提示，不出现 403 控制台错误和 TypeError
- **SC-002**: 项目详情页在 403/404/网络错误场景下 100% 展示错误状态界面，不出现空白页面、骨架屏卡死或 JavaScript 未捕获异常
- **SC-003**: 所有跳转到项目详情页的入口（全局搜索 `router.push` 到 ProjectDetail 的代码点）100% 通过统一跳转工具函数调用，不存在裸 `router.push` 跳转
- **SC-004**: 有权限用户从入口跳转到项目详情页的体验不受影响，加载时间和交互体验与修复前无显著差异（< 200ms 差异）
- **SC-005**: 错误状态界面的"返回项目列表"按钮 100% 可用，点击后成功跳转到 `/project` 路由
- **SC-006**: 针对此类 403 问题的用户支持工单/反馈减少 90% 以上（衡量标准：修复后 30 天内同类问题反馈数 ≤ 1）

## Assumptions

- 后端 `ProjectAccessScopeService` 的权限计算逻辑正确，403 响应是权限隔离的正确行为，本特性不修改后端权限模型
- 后端项目详情接口 `GET /api/projects/{id}` 在无权限时返回 403 状态码，项目不存在时返回 404 状态码，此契约保持不变
- 用户已登录系统，本特性不处理未登录场景（由现有认证中间件处理）
- 项目列表页 `/project` 已有权限过滤，用户在列表中看到的项目都是有权限的；本特性聚焦于"绕过列表的直接跳转入口"
- "返回项目列表"按钮跳转到的 `/project` 路由是用户有权限访问的（任何登录用户都能看到自己有权限的项目列表）
- 二次招标（ClosureStage.vue）创建的新项目，当前用户作为创建者必然有权限，权限校验不会误拦
- 统一跳转工具函数可复用现有 `projectStore.getProjectById`，无需新增后端权限校验接口（避免增加后端复杂度）
- 修复范围限定为前端，不涉及数据库迁移和后端代码改动
