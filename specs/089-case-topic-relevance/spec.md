# Feature Specification: 案例推荐内容相关性约束
**Feature Branch**: `agent/codex/case-topic-relevance`
**Created**: 2026-11-17
**Status**: Approved for local repair by user
**Input**: 立刻按照根因分析开始修复配送能力推荐等保证书的反复缺陷。
## User Scenarios & Testing
### User Story 1 - 内容先于客户背景（P1）
给定配送条款与同客户证书、异客户配送方案，推荐应保留配送方案，排除仅背景命中的证书。候选旧分类、置顶、中标、质量、复用次数不得改变内容适用性。
### User Story 2 - 保留正常推荐（P1）
明确证书要求仍可推荐对应证书；同主题案例仍可按客户匹配等背景加分排序；未选评分项的默认项目推荐保持可用。
## Requirements
- FR-001 有明确评分项时，标题/条款/业务子主题/资格实质要求均无内容相关性，结果必须0分并被服务排除。
- FR-002 实体及背景因素不得参与主题相关度的计算和背景加成解锁。
- FR-003 配送能力评价、配送响应速度、配送网点识别为物流配送子主题，在线离线词表保持一致。
- FR-004 沿用既有证书适用性与混合要求兼容契约，不把资质与技术一律双向互斥。
- FR-006 现场案例331的“能力”泛词及“得1分/得0分”评分模板不构成配送内容相关性；完整生产快照只在本地临时目录重放，不入库。
- FR-005 单条与批量评估、真实应用编排均覆盖根因反例；置顶不能让0分结果回流；行为测试加入既有pre-push。
## Success Criteria
同客户异主题负例0分；异客户配送正例保留；明确证书及默认推荐正例保留；根因测试RED/GREEN/撤销修复再RED；全量回归和现场验证按实际证据分别报告。
## Scope
无API/DTO/数据库变更；用户后续授权提交Gitee PR；不合并、不部署。现场40分构成尚未核实。
