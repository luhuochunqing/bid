# Feature Specification: 独立满分汇总行

**Feature Branch**: agent/codex/diagnose-1123-double-total
**Created**: 2026-11-11
**Status**: Ready for implementation
**Input**: 根据项目1123已确认根因修复，新制定计划和任务后编码。

## User Scenarios & Testing
### User Story 1 - 汇总不重复计分 (P1)
复核人员查看一张含明细和末尾“满分 | 100”的评分表，只看到明细参与计分。
**Independent Test**: 合成评分表含40/60两条明细和满分100，提取两条事实，候选合计100，声明总分100。
**Acceptance Scenarios**:
1. 给定编号/维度/分值/细则表，末尾满分与数字分列，解析后汇总不成为事实，总分证据回指原始数值格。
2. 给定初审零分表和同一方案计分表，满分100仍为计分表总分，不因多物理表丢失。
### User Story 2 - 保留单项和既有汇总行为 (P1)
编号明细中的“本项满分10分”、合法评分维度和跨行明细继续参与计分；合计/总计仍工作。
**Independent Test**: 原有金标和单项总分隔离测试通过；未验证来源人工复核语义不变。
### Edge Cases
- 独立“满分”是整行汇总标签，不是任意细则中出现“满分”就删除。
- 未声明数字、局部单项语境不得编造整表总分。
- 原有多方案、类别小计、冲突分数处理不变。

## Requirements
- FR-001: 独立汇总行只作为总分证据，不成为普通评分项。
- FR-002: 数字分格或合并格总分须保留来源锚点，抽取和总分解析对汇总标签的语义一致。
- FR-003: 正常单项满分及跨行明细不得误删；保持合计/总计兼容。
- FR-004: 候选明细100不得因表尾总分变200；未修改人工候选筛选规则。
- FR-005: 仅本地实现与验证，不重解析/采纳/改生产数据；旧15项108分另案。

## Key Entities
汇总行（标签和数字证据）、评分事实（计分明细）、原文总分（值和定位）；不改变存储模型。

## Success Criteria
- SC-001: 合成现场回放明细数2、总权重100、声明100，无满分伪评分项。
- SC-002: 新回归旧实现失败、新实现通过；恢复关键缺陷后同断言重新失败。
- SC-003: 受影响及相邻测试、金标、前端候选计算与构建通过；独立审查无未解决阻断项。
