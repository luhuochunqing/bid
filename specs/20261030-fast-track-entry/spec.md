# 评分解析快速通道优先修复

**Feature Branch**: `agent/codex/fast-track-entry-1135`
**Created**: 2026-10-30
**Status**: Approved for implementation by user
**Input**: 先落实新通道在统一入口优先执行，失败后才进入旧流程，再验证1135。

## User Scenarios & Testing
### US1 新通道优先（P1）
给定可核验完整规则和闭合分值，解析直接输出新通道结果；旧结构解析、OCR、几何归并不执行。以真实入口测试捕获调用顺序及持久化结果。
### US2 失败才兜底（P1）
给定提取异常、空结果、重复身份、父子关系歧义、规则缺失或闭合失败，新通道不得发布；旧流程执行一次并保留原审核契约。
### US3 1135验证（P1）
本地保留1135任务159的只读证据，不将客户原文提交。使用合成同构用例验证100分结构以及180分异常不被快速放行；真实文件新模型提取、上线重解析与本地回放分别记录。

## Functional Requirements
- FR01 统一任务入口先执行纯文本模型抽取与确定性核验，成功后提前完成，失败才调用旧结构路径。
- FR02 规则非空且逐字/归一化可回指原文；PR2923核验门槛至少90%，空规则不能算通过；避免自动发布任何未核验规则。
- FR03 重复评分身份、混合方案、不闭合父子关系不能以总分碰巧闭合而通过。
- FR04 已知原文总分优先；模型总分只是声明，不能以模型声明代替原文证据。未找到总分时按现有双轨100分契约尝试，审计注明来源。
- FR05 版本化快速结果须有可计算的单方案与真实文本来源，继续通过快照冻结及既有激活接口，保留手工版本保护；不新增迁移、不修改前端、不默认触发生产重解析。
- FR06 新路径在任务及运行摘要中标识DUAL_TRACK_PRIMARY，旧路径不得冒用此标记。

## Success Criteria
- SC01 成功路径旧解析调用次数为0；失败路径调用次数为1，顺序在主通道之后。
- SC02 新路径持久化候选的名称、原文规则、分值正确，空规则/重复/180分均不能快速发布。
- SC03 定向测试和金标回放通过，报告本地与线上验证边界。

## Assumptions and scope
旧引擎保留作兜底；不为1135硬编码分值修正，不删除旧管线。生产升级需单独授权。
