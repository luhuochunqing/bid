# Feature Specification: AI 评分标准解析 — 后端服务

**Feature Branch**: `agent/mimo/ai-score-parse-backend`

**Created**: 2026-08-15

**Status**: Draft

**Input**: 源自 PRD《AI 评分标准解析 — 抽屉详情》（飞书 docx D6fUdxPpJojW5Tx6cW5cyHcAnCe）后端拆分决策：后端（解析/打分/知识库匹配服务 + match 接口）先行立项，前端（PR !2292 返工）在真实 API 就绪后独立任务对齐。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 招标文件评分标准解析 (Priority: P1)

投标负责人上传招标文件后，系统自动调用 AI 解析服务，从招标文件中完整提取所有会影响投标人最终得分的评分项（含评分表之外的正文、备注、脚注、跨页内容），结构化保存为评分项清单（编号、评分项名称、详细要素、权重分值、客观/主观类别、原文依据、页码位置），并提供给前端查询消费。

**Why this priority**: 阶段 1 和阶段 2 的一切计算都建立在评分项清单之上；没有解析结果，打分、匹配、统计全部无从谈起。这是整个功能的数据地基。

**Independent Test**: 上传一份含标准评分表的招标文件（PDF/Word/Excel），轮询解析完成后查询评分项清单，可核对提取的编号、分值与原文件一致；单独交付即可验证解析质量。

**Acceptance Scenarios**:

1. **Given** 已上传含评分标准章节的招标文件，**When** 解析完成，**Then** 返回的评分项包含编号、评分项名称、详细要素（保留原文完整表述）、权重（数字）、评分类别（客观项/主观项）、原文依据与页码位置
2. **Given** 招标文件中的评分项散布于表格、正文备注、脚注，**When** 解析完成，**Then** 所有位置的评分项均被提取，不遗漏
3. **Given** 解析结果权重合计与招标文件声明总分不一致，**When** 校验执行，**Then** 系统自动触发二次解析补找缺失项，最终仍不一致时结果携带警示标记但正常返回
4. **Given** 招标文件中无任何可识别的评分标准，**When** 解析完成，**Then** 解析任务标记为失败并给出「未识别到评分标准」语义，不产生空壳成功结果
5. **Given** 多路召回识别出重复评分项，**When** 合并去重执行，**Then** 仅合并重复识别结果，语义相似但可能属于不同评分项的内容不被删除

---

### User Story 2 - 知识库五类匹配查询 (Priority: P1)

系统基于现有知识库（资质证书、人员、业绩、仓库、品牌授权五类已沉淀数据），提供五类面向评分匹配的查询接口：输入评分项要求（如"ISO9001 证书、有效期内"、"近 3 年类似业绩 ≥3 个"），输出命中记录与匹配比例，供预计得分计算消费。证书过期场景算命中但携带过期标记。

**Why this priority**: 阶段 1 预计得分完全依赖五类匹配结果；且五类匹配接口独立于 AI 解析存在，可先于解析链路交付并用确定性数据验证。

**Independent Test**: 在知识库录入确定性测试数据（如指定证书、指定人员、指定业绩数量），调用 match 接口断言命中结果与匹配比例；不依赖任何 AI 行为即可完全验证。

**Acceptance Scenarios**:

1. **Given** 知识库资质库中存在名称匹配、等级达标、有效期内的证书，**When** 调用资质 match 接口，**Then** 返回完全匹配结果与命中记录
2. **Given** 知识库人员库中部分人员符合评分项岗位与资质要求（如要求 5 人符合 3 人），**When** 调用人员 match 接口，**Then** 返回符合比例（3/5）与人员清单
3. **Given** 知识库业绩库中业绩数量未达评分项要求数量，**When** 调用业绩 match 接口，**Then** 返回实际数量与要求数量，由消费方按比例计分
4. **Given** 知识库中的证书已过有效期，**When** 调用资质 match 接口，**Then** 该证书算作命中但携带「已过期」标记
5. **Given** 知识库中无任何匹配数据，**When** 调用任一 match 接口，**Then** 返回空命中与未匹配语义，不报错、不阻断流程

---

### User Story 3 - 阶段 1 预计得分计算 (Priority: P1)

评分项清单就绪后，系统按评分项类型（资质/仓库/人员/业绩/品牌授权）调用对应知识库匹配，按 PRD 计分公式计算客观项预计得分（满分/部分得分/零分，部分得分四舍五入取整），主观项不计分（返回待确认语义），并输出每项的满足状态与评分依据（含知识库命中标记）。

**Why this priority**: 预计得分是投标负责人决定是否投标、预判竞争位置的核心决策输入，是阶段 1 的最终产出。

**Independent Test**: 给定固定评分项清单 + 确定性知识库数据，断言每项预计得分、状态（满足/不满足/待确认）与依据文本；全部为确定性计算，可完全离线验证。

**Acceptance Scenarios**:

1. **Given** 客观项知识库完全匹配，**When** 计算预计得分，**Then** 得分 = 权重满分，状态 = 满足
2. **Given** 仓库类客观项知识库部分匹配（命中证据 2/4），权重 8 分，**When** 计算预计得分，**Then** 得分 = 8 × 50% = 4 分（四舍五入取整），状态 = 待确认
3. **Given** 人员类客观项要求 5 人、知识库符合 3 人，权重 10 分，**When** 计算预计得分，**Then** 得分 = 10 × 3/5 = 6 分
4. **Given** 主观项（技术方案类描述性要求），**When** 计算预计得分，**Then** 不产生数字得分，返回待确认语义且不计入合计
5. **Given** 知识库无该客观项任何数据，**When** 计算预计得分，**Then** 仓库类得 0 分状态不满足；评分依据注明知识库未匹配
6. **Given** 全部评分项计算完成，**When** 生成汇总，**Then** 输出预计得分合计（仅客观项）、满足/不满足/待确认计数、客观项与主观项权重合计

---

### User Story 4 - 阶段 2 投标文件实际打分 (Priority: P2)

投标负责人上传投标文件后点击「AI 实际打分」，系统解析投标文件全文，将每个客观项评分标准与标书应答内容对标匹配，计算实际得分，输出评分依据、标书引用原文（含章节页码，无对应内容时返回明确的空语义）、缺失说明与修改建议；主观项保持待确认并附 AI 修改建议。

**Why this priority**: 实际打分是阶段 2 的核心价值——投标前自检标书响应完整度；但它依赖阶段 1 评分项清单先就绪，故列为 P2。

**Independent Test**: 给定已解析项目 + 投标文件，触发打分后轮询结果，断言客观项得分在 [0, 权重] 区间、主观项无数字得分、每项携带依据与引用；标书未响应的项得 0 分。

**Acceptance Scenarios**:

1. **Given** 客观项标书完全响应，**When** 打分完成，**Then** 实际得分 = 权重满分，输出评分依据与标书引用原文（含章节与页码）
2. **Given** 客观项标书提供替代方案（如 CMMI 3 替代 5 级），**When** 打分完成，**Then** 按匹配比例给部分得分，依据说明替代方案情况，缺失说明与修改建议非空
3. **Given** 标书中找不到某评分项对应内容，**When** 打分完成，**Then** 该项得 0 分状态不满足，标书引用返回空语义，依据注明标书未响应
4. **Given** AI 输出的得分超出 [0, 权重] 范围，**When** 后端校验，**Then** 该项得分置空标记待确认，异常记录日志，不阻断其余评分项
5. **Given** 主观项，**When** 打分完成，**Then** 实际得分为空（待确认语义），仅输出 AI 修改建议
6. **Given** 投标文件解析失败，**When** 打分任务结束，**Then** 所有客观项实际得分置空、状态待确认，任务携带失败原因，上次成功打分结果不被破坏

---

### User Story 5 - 触发控制与超时保护 (Priority: P2)

系统控制两阶段的触发时机与前置条件：阶段 1 由招标文件上传自动触发；阶段 2 由用户显式触发且要求标书已上传、评分标准已解析；重新解析/重新打分覆盖旧结果但保留对方结果。解析与打分任务超过 30 分钟自动终止并保留上次成功结果。

**Why this priority**: 保证异步任务的生命周期安全——不合法的触发被拒绝、失败不破坏已有结果、超时不无限挂起；是前三条故事可靠运行的保护层。

**Independent Test**: 构造未上传标书即打分、未解析即打分、解析中重复触发等场景，断言接口拒绝语义与任务状态流转；超时用缩短的测试时钟模拟验证。

**Acceptance Scenarios**:

1. **Given** 投标文件未上传，**When** 用户请求实际打分，**Then** 请求被拒绝并返回需先上传标书的明确语义
2. **Given** 评分标准尚未解析完成，**When** 用户请求实际打分，**Then** 请求被拒绝并返回需先完成解析的明确语义
3. **Given** 解析任务运行超过 30 分钟，**When** 超时生效，**Then** 任务终止、记录失败日志、上次成功解析结果保留可用
4. **Given** 已有打分结果，**When** 用户重新解析且评分项发生变化，**Then** 解析结果覆盖，打分结果按 PRD 标记需重新打分
5. **Given** 用户重新打分，**When** 完成，**Then** 仅覆盖打分结果，评分标准不变

---

### Edge Cases

- 招标文件格式不支持（非 PDF/Word/Excel）或超过 50MB：上传与后端双重校验拒绝，返回明确提示
- 评分项编号重复：去重保留首次出现，后端日志记录，不提示用户
- 权重合计 ≠ 100：不阻断流程，正常返回并携带实际总分与警示标记
- 权重合计 = 0 或评分项数量 = 0：判定解析失败，返回空状态语义（前端展示「尚未解析到评分标准」引导重新解析）
- 报价类评分项：归主观项处理，AI 不打分
- 知识库证书过期：命中但标记已过期，状态待确认，依据注明需补充说明或更新
- LLM 结构化输出不完整（缺字段、权重非数字）：字段级容错，无法解析的评分项丢弃并记日志，不产生半残记录
- 并发触发同一项目的解析/打分：任务级互斥，后触发请求返回任务进行中语义
- 用户无该投标任务访问权限：所有查询与触发接口统一拒绝，返回无权限语义

## Requirements *(mandatory)*

### Functional Requirements

**解析（阶段 1）**

- **FR-001**: 系统 MUST 在招标文件上传后自动触发解析，采用四路召回并行（关键词及规则、文档结构、评分规则语义、LLM 全文语义），各路结果统一进入候选池，不设前后覆盖
- **FR-002**: 系统 MUST 对候选池内容做 LLM 结构化提取，每个评分项产出：编号、评分项名称、详细要素（完整保留原始要求不得摘要）、权重（数字）、评分类别（客观/主观）、评分规则上下文、原文依据、页码位置
- **FR-003**: 系统 MUST 按客观/主观判定规则分类：含量化条件（具备证书/响应条款/配置人员）判客观项；描述性要求（方案合理/可行/完善）判主观项
- **FR-004**: 系统 MUST 对多路召回结果按原文位置、名称、规则、语义相似度、表格行列关系合并去重，且 MUST NOT 因语义相似删除可能独立的评分项
- **FR-005**: 系统 MUST 执行两层分值闭环校验（总分校验 + 维度级校验），差异时自动触发二次解析定向补找
- **FR-006**: 系统 MUST 执行评分项数量校验（表格行数、编号连续性、分值合计），发现缺失触发回补解析；回补仍差异时触发完整性校验 Agent 重点扫描脚注、备注、跨页引用
- **FR-007**: 系统 MUST 持久化解析结果（评分项清单及汇总统计）并提供按项目的查询接口，重新解析覆盖旧结果

**知识库匹配**

- **FR-008**: 系统 MUST 复用现有五类知识库数据（资质证书、人员、业绩、仓库、品牌授权），提供五个匹配查询接口，输入评分项要求，输出命中记录与匹配情况，接口语义与 PRD §4.2 一致
- **FR-009**: 资质匹配 MUST 按证书名称关键词 + 等级达标 + 有效期三条件判定，输出完全匹配/部分匹配/未匹配三档；过期证书算命中但 MUST 携带过期标记
- **FR-010**: 人员匹配 MUST 输出符合要求的人员比例与清单；业绩匹配 MUST 输出实际数量与要求数量；仓库与品牌授权匹配 MUST 输出完全/部分/未匹配三档

**打分计算（两阶段）**

- **FR-011**: 系统 MUST 按评分项类型执行阶段 1 预计得分：资质/仓库/品牌授权类分档计分（完全 = 权重，部分 = 权重 × 命中证据比例，未匹配 = 0）；人员类比例计分（权重 × 符合人数/要求人数）；业绩类数量计分（权重 × 实际数量/要求数量）
- **FR-012**: 系统 MUST 按同构规则执行阶段 2 实际得分，匹配数据源为投标文件应答内容，并输出评分依据、标书引用原文（含章节页码）与匹配比例（0~100%）
- **FR-013**: 部分得分 = 权重 × 匹配比例 MUST 四舍五入取整数，取值范围开区间 (0, 权重)
- **FR-014**: 主观项与报价类评分项 MUST NOT 产生数字得分（返回空/待确认语义），MUST NOT 计入合计得分；主观项 MUST 附 AI 修改建议（阶段 2）
- **FR-015**: 满足状态判定 MUST 遵循：客观项满分 = 满足；零分 = 不满足；部分得分或证书过期 = 待确认；主观项 = 待确认
- **FR-016**: 系统 MUST 校验 AI 得分在 [0, 权重] 区间，超出的项得分置空并标记待确认，记录异常日志
- **FR-017**: 系统 MUST 输出汇总统计：预计/实际得分合计（仅客观项）、满足/不满足/待确认计数、客观项与主观项权重合计
- **FR-018**: 阶段 1 评分依据 MUST 携带知识库命中标记；阶段 2 输出 MUST NOT 携带知识库命中标记

**触发、异步与异常**

- **FR-019**: 阶段 2 打分 MUST 校验前置条件（标书已上传且评分标准已解析完成），不满足时返回明确的拒绝语义
- **FR-020**: 解析与打分 MUST 异步执行并提供进度查询；任务超过 30 分钟 MUST 自动终止、记录失败日志、保留上次成功结果
- **FR-021**: 重新解析 MUST 覆盖解析结果且当评分项变化时标记打分结果需重算；重新打分 MUST 仅覆盖打分结果
- **FR-022**: 权重合计 ≠ 100 时 MUST NOT 阻断，返回实际总分并携带警示标记
- **FR-023**: 所有接口 MUST 校验用户对所属投标任务的访问权限，无权限返回统一拒绝语义
- **FR-024**: 知识库无匹配数据、标书未响应等空数据场景 MUST 正常返回零分/空语义结果，MUST NOT 抛错阻断

### Key Entities *(include if feature involves data)*

- **ScoreItem（评分项）**: 从招标文件提取的评分项，属性含编号、评分项名称、详细要素、权重、评分类别、满足状态、原文依据、页码位置、所属项目关联
- **ScoreResult（打分结果）**: 评分项的得分与依据，属性含预计得分、实际得分、评分依据、标书引用、知识库命中标记、缺失说明、修改建议、匹配比例
- **五类知识库匹配视图**: 资质证书（名称/等级/有效期）、人员（岗位/资质）、业绩（类型/时间/金额）、仓库（名称/位置/面积/设施）、品牌授权（品牌/范围/有效期）——物理存储复用现有知识库模块，本特性仅消费其匹配视图

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在不少于 20 份真实招标文件的测试样本集上，解析权重合计与文件声明总分的一致率 ≥ 95%（经自动二次解析后）
- **SC-002**: 在确定性标注样本集上，客观项实际得分与人工标注一致率 ≥ 90%
- **SC-003**: 主观项与报价项的数字得分泄漏为 0（任何输出渠道均不得出现数字得分）
- **SC-004**: 解析/打分任务 30 分钟超时保护生效率 100%，超时后上次成功结果可查询率 100%
- **SC-005**: 单个评分项的五类知识库匹配（不含 LLM 调用）合计耗时 ≤ 5 秒
- **SC-006**: 无任务访问权限用户调用任一接口被拒绝率 100%，且错误语义明确指向权限
- **SC-007**: 解析失败（0 评分项）场景 100% 返回失败语义，不产生空壳成功结果

## Assumptions

- LLM 调用基础设施复用现有投标文件 Agent（biddraftagent）的模型集成与文件解析能力，不新建模型通道
- 文件存储复用现有文件存储服务，本特性仅按 URL 引用
- 异步进度获取采用轮询模式（与标讯批量导入异步化 spec 031 的既有模式一致），不引入 WebSocket
