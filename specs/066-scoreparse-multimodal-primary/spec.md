# Feature Specification: 多模态模型主导评分项解析

**Feature Branch**: `agent/codex/scoreparse-multimodal-primary`  
**Created**: 2026-09-20  
**Status**: Approved for implementation

## User Scenarios & Testing

### User Story 1 - 从真实版面完整提取评分项 (Priority: P1)

投标负责人触发评分标准解析后，系统结合招标文件页面图像、表格网格和原始单元格，一次性生成完整评分项。每项包含章节、原始序号、父子关系、最高分、完整规则、页码和单元格定位，不能把报价品类权重表、资格审查表或响应模板误当评分表。

**Independent Test**: 用项目 35、43、1118 的脱敏生产版式回放，完整覆盖有效评分项，包含项目 35 的响应报价 30 分，总分与原文声明一致。

**Acceptance Scenarios**:

1. **Given** 评分表跨页且续页没有重复表头，**When** 解析，**Then** 全部续表项归入同一章节并保持物理顺序。
2. **Given** 文档同时含报价品类权重表和正式评分表，**When** 解析，**Then** 权重表不产生评分事实，正式报价评分项必须产生事实。
3. **Given** 单元格含合并区域或长文本，**When** 解析，**Then** 父项和叶子项分别建模并可回溯页码及来源单元格。

### User Story 2 - 证据校验后自动发布，异常才审核 (Priority: P1)

系统对模型结果执行确定性验证。序号、总分、父子分值、原文引用和重复项均通过时自动发布；任一验证失败时不覆盖已有正式结果，展示完整候选、差异和证据，允许用户修正后采纳。

**Independent Test**: 自洽的 100 分候选自动落库；引用不存在、总分不闭合或序号冲突的候选进入 `REVIEW_REQUIRED` 且原正式项不变。

**Acceptance Scenarios**:

1. **Given** 叶子分值等于声明总分且引用逐字存在，**When** 校验完成，**Then** 自动发布且无需人工审核。
2. **Given** 任一引用无法在来源单元格定位，**When** 校验，**Then** 阻止发布并指出事实、字段、模型值和来源值。
3. **Given** 用户修改异常候选，**When** 重新验证通过并采纳，**Then** 发布修正结果并保留审计快照。

### User Story 3 - 独立且可解释的主客观分类 (Priority: P1)

证书、资质、数量、金额、日期、阶梯区间、固定公式和可验证满足条件属于客观项；横向比较、酌情评分、优良中差属于主观项。混合规则标记需复核，不能整表统一分类。

**Independent Test**: 项目 580 的销售额、信用额度、免费配送起订额和折扣率为客观项；方案横向比较为主观项；项目 1117 的证书与业绩为客观项。

### User Story 4 - 证书和业绩逐条件可审计评分 (Priority: P1)

预计得分展示具体命中记录以及每个条件的通过、失败或缺证据状态。业绩核验时间、金额、同类业务、合同或中标证明、付款流水、发票等原文要求；证书核验证书类型、等级、有效期和主体。不得用总命中数或模糊比例替代条件证明。

**Independent Test**: 项目 1117 的管理体系显示对应证书记录；公司业绩只有同时满足全部必选条件的记录计分，不再输出不可追溯的“131/1”。

### User Story 5 - 完整可读的异常复核体验 (Priority: P2)

复核人员能展开查看完整规则、原文、页面与单元格位置、模型输出和校验差异，能逐项修改序号、名称、分值、分类、父项与规则，并在重新验证通过后采纳。

**Independent Test**: 长规则不再单行省略；键盘和鼠标均能打开详情；错误总分时阻止直接发布并列出差异。

## Edge Cases

- 页面图片缺失但网格完整时可以继续，但模型不得声称看到了图片证据。
- 模型超时、输出非法或引用越界时保留旧正式项并进入异常复核，不回退为正则自动发布。
- 不同章节可分别从 1 开始，按章节局部连续验证，禁止跨章节全局扁平排序。
- 父项不重复计分；父项声明与子项合计冲突时阻止发布。
- 报价固定公式属于可计算客观项；缺少基准价时状态为待计算，不改判主观。
- 知识记录只满足部分条件时不得计算为完整命中。
- 仅向模型发送当前评分页及必要邻页，禁止全文件无界发送。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 将评分相关页面图像、表格网格、原始单元格文本及坐标组合为一次结构化模型请求。
- **FR-002**: 模型 JSON MUST 为每项提供章节、code、parentCode、dimension、weight、ruleText、scoreType、pageNumber、sourceCellIds、quotedText 和 confidence。
- **FR-003**: Java 规则 MUST NOT 作为主召回器；现有启发式仅可产生诊断或待复核候选，禁止自动发布。
- **FR-004**: 验证器 MUST 检查章节内序号连续性并允许不同章节各自从 1 开始。
- **FR-005**: 验证器 MUST 检查叶子总分闭合、父项与直接子项合计一致，父项不得重复计分。
- **FR-006**: `quotedText` MUST 在指定原始单元格逐字存在，页码和单元格 ID MUST 属于输入资产。
- **FR-007**: 验证器 MUST 识别相同来源重复引用及同章节同 code 冲突。
- **FR-008**: 只有全部强校验通过的运行才能覆盖正式评分项并触发预计得分。
- **FR-009**: 任一强校验失败 MUST 保留已有正式项，并保存完整候选、差异、原因和证据供复核。
- **FR-010**: 复核界面 MUST 展示完整规则与原文，并提供详情及逐项编辑能力。
- **FR-011**: 主客观分类 MUST 独立产生，不得由知识库是否命中决定。
- **FR-012**: 明确阶梯、证书、数量、金额、日期、公式和布尔满足条件 MUST 分类为 OBJECTIVE。
- **FR-013**: 横向比较、酌情、主观评价和优良中差 MUST 分类为 SUBJECTIVE；混合规则 MUST 复核。
- **FR-014**: 证书匹配 MUST 返回记录标识、名称、主体、有效期以及各要求的 PASS/FAIL/MISSING_EVIDENCE。
- **FR-015**: 业绩匹配 MUST 返回案例标识、客户、合同日期、金额、业务类别及各条件证明。
- **FR-016**: 预计得分只能使用全部必选条件均通过的记录；缺证据不得视为通过。
- **FR-017**: API MUST 保持 `/items`、`/review`、`/parse/status` 兼容并增量提供解析来源、差异和条件证明。
- **FR-018**: 模型调用 MUST 记录模型、耗时、图片数、页码范围、token、验证结果与失败原因，不记录正文。
- **FR-019**: 多模态关闭或不可用时 MUST 进入可见复核，不得静默用正则结果自动发布。
- **FR-020**: 五个生产项目脱敏回放 MUST 作为发布门禁，验证项数、总分、顺序、分类与证据。

### Key Entities

- **MultimodalScoreFact**: 模型生成的结构化评分事实。
- **ScoreFactValidationReport**: 运行级和事实级验证结果。
- **EvidenceLocator**: 页码、表 ID、单元格 ID、坐标和逐字引用。
- **KnowledgeCondition**: 从评分规则拆出的单一证书或业绩条件。
- **KnowledgeRecordProof**: 某知识记录对每个条件的判定与证据。

## Success Criteria

- **SC-001**: 五个指定项目脱敏回放评分项召回率 100%，错误评分表召回为 0。
- **SC-002**: 自动发布运行的总分闭合率和来源逐字定位率均为 100%。
- **SC-003**: 项目 580 九项顺序与原文一致，四类可计算规则分类准确率 100%。
- **SC-004**: 项目 1117 的证书和业绩均可下钻到具体记录和全部条件，不出现聚合计数满分依据。
- **SC-005**: 校验失败时正式项零覆盖，复核页可完整查看和修改候选字段。
- **SC-006**: 典型 100 页文件在模型正常时 120 秒内完成；模型超时时 10 秒内进入明确失败或复核状态。
- **SC-007**: 既有金标、架构、Sidecar、前端测试和构建全部通过。

## Assumptions

- 复用现有多模态模型和结构化输出基础设施，不增加模型供应商。
- 复用既有 Sidecar 图片能力；只有现有契约确实不足时才扩展。
- 人工修改继续通过现有 review/adopt 审计链保存。
- 优先复用现有 fact/evidence/review JSON 字段，不新增数据库表。

## Out of Scope

- 不改变实际打分阶段的专家职责。
- 不重新设计知识库录入流程。
- 不部署、不批量重解析、不直接修生产数据。
