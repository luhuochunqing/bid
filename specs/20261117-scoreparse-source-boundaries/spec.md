# Feature Specification: 评分解析来源与规则边界修复
**Feature Branch**: `agent/zcode/scoreparse-1133-toc-diagnosis`
**Created**: 2026-11-17
**Status**: Approved for implementation
**Input**: 用户要求按项目1133修复计划执行；范围为本地修复和验证。

## User Scenarios & Testing
### User Story 1 - 正确定位评分方案与条款 (Priority: P1)
用户解析含目录、方法说明、材料清单和正文评分表的文件，只得到真实评分方案，评分引用不来自材料清单。
**Independent Test**: 真实1133输入及去敏回归样本，从作用域和证据绑定到原文校验。
**Acceptance Scenarios**:
1. Given 目录以点线及横线包围页码，When 定位章节，Then 目录不是评分方案。
2. Given 前附表说明采用综合评分法，When 定位方案，Then 该说明不是独立方案，真实多方案仍保留。
3. Given 同名短标题在材料清单出现，When 绑定评分原文，Then 材料清单不充当评分规则，无证据时保留待复核。
### User Story 2 - 规则完整且类型正确 (Priority: P1)
**Independent Test**: 1133分档规则及跨页、汇总边界对照。
**Acceptance Scenarios**:
1. Given 主观分档有数字，When 分类，Then 不因数字或未提供得0分改判客观。
2. Given 仓储行后为合计，When 恢复原文，Then 不吞汇总行，合法跨页续文不丢失。
### Edge Cases
真实双标包；附件承载评分表；文本型评分；同名多处引用；合同考核；报价公式；量化门槛；评分细则的材料要求；首末列留空的真实续行。
## Requirements
- FR-001: 方案必须由真实评分章节承载，目录及方法说明不得成为独立根。
- FR-002: 评分引文须位于正确范围，短标题唯一出现不等于规则证据充分。
- FR-003: 汇总行不得并入评分项，真实跨页规则完整保留。
- FR-004: 按评分机制识别主客观，分档评价优先于无语义数字匹配。
- FR-005: 项目1133目标12项100分，6主观6客观；不将分类汇总作为计分项。
- FR-006: 历史任务只读；不依靠放宽来源或总分门禁达成自动通过。
- FR-007: 必须有同一断言RED/GREEN及关键修复撤销后失败的证据。
### Key Entities
方案、原文范围、评分事实、逻辑规则单元、复核候选与正式版本，沿用既有契约。
## Success Criteria
- SC-001: 真实文件12个名称和分值逐项吻合，合计100，三项分类无重复计分。
- SC-002: 六项描述性分档判主观；六项可验证条件/公式判客观。
- SC-003: 引文无材料清单误引、无合计行污染、跨页规则完整。
- SC-004: 相邻既有回归通过；日志/数据库/API/UI线上验收在部署后独立报告。
## Assumptions
本轮仅修改工作区，无部署、生产重解析或采纳授权。客户文件留本地，Git只存合成夹具。
