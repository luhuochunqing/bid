# Feature Specification: 项目1359评分满分与综合权重修复

**Feature Branch**: `agent/codex/074-fix-1359-score-contract`
**Created**: 2026-10-08
**Status**: Approved direction, implementation scoped by evidence
**Input**: 用户批准恢复完整1359评分规则、最低/最高小计列修正、完整性及权重验证，保留已有修复。

## User Scenarios & Testing

### User Story 1 - 正确验证评分表满分 (Priority: P1)
使用者解析包含最低分和最高分的真实评分表，系统按最高分核验满分。
**Independent Test**: 1359商务和技术原始满分均100，小计不会取12或38。
**Acceptance Scenarios**:
1. 有明确最高分列，最低分同时存在，小计只读最高分；最低分在左或右均一致。
2. 单个明确分值列仍保持原行为；不明确多数字列不猜最高分。
3. 同一可信满分列出现不同合计值，继续阻断。

### User Story 2 - 完整综合权重规则 (Priority: P1)
使用者取得与原文一致的原始明细和最终贡献，技术50、商务20、价格30，共100。
**Independent Test**: 全部类别和来源完整时贡献闭环；缺价格、模型仅总括事实、未知比例均不能声明完整恢复。
**Acceptance Scenarios**:
1. 原始技术、商务100分分别使用原文50%、20%；原始价格100分使用30%。
2. 原始分值保留供来源核验；评分标准的原始分与贡献不混用；旧自动评分器对小数贡献取整不守恒，用户明确接受本次暂不使用AI实际打分。
3. 同名不同包、比例冲突、最低分当满分、缺类别、无来源规则均不可自动生效。

### User Story 3 - 受控恢复并保持既有保护 (Priority: P1)
使用者按用户明确授权通过备份、项目限定事务SQL恢复1359，更新前有完整来源明细与版本校验，更新后实际数据与页面一致。
**Independent Test**: 旧规则在候选不完整或审核失败时保持逐项不变；完整验证和审查通过后才允许生效。
**Acceptance Scenarios**:
1. 保留来源验证、方案资格、父子去重、待复核不覆盖旧规则。
2. 保留当前满足状态并缩放已有预计分；用户明确接受AI实际打分暂不可用，本次不触发打分。
3. 现有接口无法补齐明细，使用用户授权的直接数据库修复；不部署、不启用版本开关。

### Edge Cases
百分比出现在覆盖率等规则而非综合权重；最低/最高列换序；负扣分；两包比例相同或不同；不完整候选；表头缺失；小计合并格错位；现有100分直接计分项目。

## Requirements
- FR-001 小计必须与可信列语义一致，未知或冲突仍待复核。
- FR-002 原始满分、综合比例与贡献分别保存或以可复核材料表达，不把原始200分除2。
- FR-003 完整性必须包含技术、商务和价格规则，模型总括100不能代替明细。
- FR-004 不绕过权限、来源、方案、父子、版本/发布校验。
- FR-005 真实1359原文及既有Golden集合回归；独立审查代码和反例。
- FR-006 恢复必须使用用户授权的项目限定数据库事务，具备前后数据库和页面证据；不可把本地通过写成线上恢复。

## Key Entities
评分原文、最高分列、原始评分单位、分部比例、综合贡献、候选快照、正式生效版本。

## Success Criteria
- SC-001 1359两张明细表满分都为100，最低合计12/38不成为满分。
- SC-002 完整明细贡献按原文闭合50+20+30=100，缺价格时明确不完整。
- SC-003 既有Golden准确率不下降，来源与发布保护反例仍拒绝。
- SC-004 1359真实受控生效后正式数据与UI一致100；未生效时明确未完成。

## Assumptions and Delivery Boundary
用户已经批准设计方向；用户后续“提交PR”授权提交并推送源码到Gitee PR，不授权merge/deploy。用户追加授权1359数据库直接修复，明确不部署、不打开版本生效开关。保护规则不能为恢复便利放宽。无API能力的恢复不模拟成功。

## 2026-10-08 范围裁定
用户回复“限定恢复评分标准，接受AI实际打分暂不可用”。因此本次恢复只证明评分标准39/100、原文、分类、满足状态、来源及人工审计。旧评分器小数取整和价式参数检查仍未修复，按钮未强制禁用，不声称实际打分可用，不执行该功能。

验收范围经用户裁定：只恢复评分标准39/100，AI实际打分暂不可用，按钮未强制禁用。MySQL修复/回滚全部DML封装在临时存储过程的EXIT HANDLER（ROLLBACK/RESIGNAL）内，即使客户端--force继续也不能部分提交。
