# Feature Specification: 评分依据可信度与中文可读性

**Feature Branch**: `agent/codex/fix-score-evidence-clarity`

**Created**: 2026-09-20

**Status**: Draft

**Input**: 项目 1117 公司业绩显示满分，但依据不明确且案例库未搜索到相关业绩；详情中的英文内部术语应全部改为中文，解释应清晰易懂。

## User Scenarios & Testing

### User Story 1 - 不完整证据不得自动给满分 (Priority: P1)

投标负责人希望系统只在能够证明招标条款全部强制条件时给出预计分；缺少付款流水、发票等必备证明时应提示人工核验。

**Why this priority**: 错误满分会直接误导投标决策，属于评分数据完整性缺陷。

**Independent Test**: 构造项目 1117 同类条款以及任意数量候选；只要缺少强制证明，预计得分必须为空且状态为待确认。

**Acceptance Scenarios**:

1. **Given** 条款要求日期、金额、客户清单、付款流水和发票，**When** 系统只能验证日期、金额及候选记录，**Then** 不自动给分并列出待核验材料。
2. **Given** 全部条件都能由系统资料证明，**When** 合格记录达到满分数量，**Then** 保持既有计分规则。
3. **Given** 找到很多候选，**When** 任一强制条件不能证明，**Then** 候选数量不得表述为有效业绩数量。

### User Story 2 - 清楚说明来源和证据缺口 (Priority: P1)

用户希望区分“找到了候选资料”和“已经证明满足全部条件”，并知道下一步需要核验什么。

**Why this priority**: 清晰依据是判断预计分可信度的前提。

**Independent Test**: 证据不足时，依据必须出现数据来源、候选数量、已核验条件和待核验条件，且不得声称命中有效业绩。

**Acceptance Scenarios**:

1. **Given** 业绩库存在候选但证明不完整，**When** 打开详情，**Then** 显示“找到候选业绩资料，但尚不能确认有效业绩”。
2. **Given** 案例库没有搜索结果，**When** 查看得分来源，**Then** 明确当前预判读取业绩库而非案例库。

### User Story 3 - 详情信息全部业务中文化 (Priority: P2)

业务用户只看到可理解的中文名称和状态，不需要理解技术管道、算法层级或英文状态码。

**Why this priority**: 内部英文降低可读性，也容易让用户误把技术状态当成评分证据。

**Independent Test**: 使用包含所有已知内部枚举的评分项打开详情，页面不出现内部英文值并显示中文解释。

**Acceptance Scenarios**:

1. **Given** 接口返回内部提取来源和校验状态，**When** 打开详情，**Then** 页面使用中文业务名称。
2. **Given** 依据含算法层级或记录类型代码，**When** 查看依据，**Then** 页面不显示内部代码。

### Edge Cases

- 只要求数量和日期、没有缺失附件要求的条款不应一律降级。
- “合同无金额时可用中标通知书”等替代证据无法自动读取时，应提示人工核验。
- 候选为零时说明业绩库未找到候选，不得提及案例库命中。
- 不自动批量改写历史评分结果。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 区分候选业绩资料与满足全部条件的有效业绩。
- **FR-002**: 存在无法核验的强制材料时，系统 MUST 保持待确认，MUST NOT 自动给分。
- **FR-003**: 系统 MUST 识别签约日期、合同金额和所需数量约束。
- **FR-004**: 证据不足的依据 MUST 说明业绩库候选数量、已核验条件和待人工核验材料。
- **FR-005**: 页面 MUST 明确预判来源是业绩库，不得用“知识库命中”暗示案例库已有对应内容。
- **FR-006**: 用户可见的提取来源、校验状态和证据状态 MUST 使用中文。
- **FR-007**: 用户可见依据 MUST NOT 包含内部算法、管道或状态代码。
- **FR-008**: 简单且全部条件可自动核验的条款 MUST 保持既有计分能力。
- **FR-009**: 本功能 MUST NOT 自动修改生产评分结果或触发生产重算。

### Key Entities

- **评分项**: 招标评分要求及其预计分、状态和依据。
- **业绩候选资料**: 通过部分条件筛选的业绩库记录，不等同于有效业绩。
- **证据要求**: 分为系统可核验与待人工核验的条款条件。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 项目 1117 同类条款在证据不完整时错误满分发生率为 0%。
- **SC-002**: 100% 的证据不足场景展示至少一个待人工核验条件。
- **SC-003**: 已知内部英文枚举和算法代码的用户可见泄漏数量为 0。
- **SC-004**: 既有简单、证据完整的业绩计分回归场景通过率为 100%。

## Assumptions

- 阶段 1 使用现有业绩库预判；案例库是独立数据源。
- 现有业绩记录不能证明付款流水和发票真实性。
- 无法自动证明不等于不满足，默认应待人工核验而非零分。
- 部署和生产重算需要另行授权。
