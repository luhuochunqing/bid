# Feature Specification: 项目三表单已有字段锁定 + 自定义字段扩展

**Feature Branch**: `agent/claude/co601-project-form-custom-fields`

**Created**: 2026-07-31

**Status**: Draft

**Input**: Linear CO-601 — 项目三个表单（project.basic / project.initiation / project.detail）已有字段不允许更改，但管理员希望能新增自定义字段，且新增字段的数据要真正提交保存到后端（完整方案）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员为项目表单配置自定义字段并在业务流程中生效 (Priority: P1)

管理员在表单设计器中打开项目相关表单（基本信息、立项、详情三个之一），在保留全部系统预置字段的前提下，添加一个自定义字段（如"客户预算等级"），保存并发布。业务用户随后在项目创建向导或立项页面看到该字段、填写值并提交；该值被系统保存，并在后续查看该项目时正确回显。

**Why this priority**: 这是本特性的核心价值——让项目表单具备可扩展性，满足"不同项目需要采集额外信息"的业务诉求，同时数据必须真实落库，不接受"能填但提交即丢弃"的假功能。

**Independent Test**: 管理员新增一个文本字段并发布 → 业务用户在项目表单中填写该字段并提交 → 重新打开该项目确认字段值完整回显。此链路独立验证了本特性的端到端价值。

**Acceptance Scenarios**:

1. **Given** 管理员已打开发布状态的 project.basic 表单，**When** 添加自定义字段"客户预算等级"（文本类型）并保存发布，**Then** 项目创建向导的基本信息步骤渲染出该字段
2. **Given** 业务用户在该字段填入"重点客户"并提交创建项目，**When** 提交完成后，**Then** 该字段值已持久化保存，重新打开项目详情可见"重点客户"
3. **Given** project.initiation 表单已添加自定义字段，**When** 用户在立项页填写并提交立项，**Then** 该字段值随立项信息一并保存，审批/查看时可见

---

### User Story 2 - 系统预置字段防误改保护 (Priority: P2)

管理员在设计器中编辑项目表单时，系统预置字段（业务流程依赖的字段，如项目名称、项目经理、保证金等）的字段 key 和字段类型不可修改、不可删除，从机制上防止"管理员误改预置字段导致业务流程断裂"。

**Why this priority**: 这是安全护栏。放开"新增"能力后，必须同时收紧"改动预置字段"的风险敞口，否则扩展能力反而引入流程断裂风险。当前 project.basic 完全无保护（可改可删），project.initiation / project.detail 则是整表只读连新增也被禁止，两端都需要归位。

**Independent Test**: 管理员尝试修改任一预置字段的 key 或类型、尝试删除预置字段，界面应禁用相关操作入口。

**Acceptance Scenarios**:

1. **Given** 管理员打开 project.basic 表单设计器，**When** 尝试修改系统预置字段的 key 或类型，**Then** 对应输入控件为禁用状态
2. **Given** 管理员打开 project.initiation 表单设计器，**When** 查看预置字段行，**Then** 删除按钮不展示或不可用
3. **Given** 管理员打开任一项目表单，**When** 查看自定义字段行，**Then** 编辑、删除、拖拽排序均可用（与预置字段形成明显区分）

---

### User Story 3 - 自定义字段全生命周期管理 (Priority: P3)

管理员可对已添加的自定义字段进行编辑（label、必填、占位提示等）、停用、删除；被删除的自定义字段不再渲染，但历史项目已保存的字段值仍保留在系统中不丢失。

**Why this priority**: 完整的字段管理能力提升长期可维护性，但相对 P1 主链路属于增强项。

**Independent Test**: 编辑自定义字段 label 后业务页展示更新；删除字段后新表单不再渲染该字段，历史数据查询仍可追溯。

**Acceptance Scenarios**:

1. **Given** 已发布含自定义字段的表单，**When** 管理员修改该字段 label 并重新发布，**Then** 业务页展示新 label，已保存的字段值不受影响
2. **Given** 某自定义字段已被多个项目填写，**When** 管理员删除该字段，**Then** 新表单不再渲染该字段，历史项目的已存值仍在数据库中保留

---

### Edge Cases

- 自定义字段 key 与系统预置字段 key 重复时，系统必须拒绝保存并给出明确提示
- 自定义字段 key 之间重复时，系统必须拒绝保存
- 表单已发布且已有项目填写了自定义字段后，管理员修改该字段类型（如文本改下拉），历史值的展示必须不报错（按文本兜底展示）
- 项目表单设计器在保存/发布时网络失败，草稿内容不丢失
- 项目历史数据（特性上线前创建的项目）打开表单时，自定义字段区域正常渲染为空值，不报错

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许管理员在 project.basic、project.initiation、project.detail 三个表单范围内新增自定义字段
- **FR-002**: 系统 MUST 禁止修改三个表单内系统预置字段的字段 key 与字段类型
- **FR-003**: 系统 MUST 禁止删除三个表单内的系统预置字段
- **FR-004**: 系统 MUST 允许管理员编辑、删除、拖拽排序自定义字段
- **FR-005**: 系统 MUST 对三个表单开放保存草稿与发布操作（当前 project.initiation / project.detail 为整表只读，需解禁为"预置字段锁定 + 自定义字段可编辑"）
- **FR-006**: 系统 MUST 在保存/发布时校验自定义字段 key 的唯一性（不与预置字段重复、自定义字段之间不重复），冲突时拒绝并提示
- **FR-007**: 系统 MUST 将业务用户在自定义字段中填写的值随项目创建/立项/详情提交流程持久化保存
- **FR-008**: 系统 MUST 在项目详情、创建向导、立项页重新打开时正确回显自定义字段的已保存值
- **FR-009**: 系统 MUST 在界面上区分系统预置字段与自定义字段（如锁定标识），让管理员清楚哪些字段受保护
- **FR-010**: 系统 MUST 保证特性上线前已存在的历史项目数据在表单中正常打开、自定义字段显示为空值
- **FR-011**: 被删除的自定义字段 MUST NOT 再渲染，但其历史已保存值 MUST 保留在系统中不丢失

### Key Entities *(include if feature involves data)*

- **表单定义（Form Definition）**: 一个表单范围（scope）的结构描述，含系统预置字段与自定义字段两类字段；预置字段由系统定义并锁定，自定义字段由管理员扩展
- **项目自定义字段值（Project Custom Field Values）**: 业务用户在表单自定义字段中填写的数据，归属于具体项目，随项目生命周期保存与回显
- **系统预置字段清单（Locked Field Inventory）**: 三个表单范围内被业务流程硬编码依赖、需要锁定保护的字段集合

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可在 5 分钟内完成"新增自定义字段 → 保存 → 发布"全流程，业务页立即可见
- **SC-002**: 自定义字段填写值随业务提交的保存成功率 100%，重新打开项目时值回显一致
- **SC-003**: 系统预置字段的 key/类型修改与删除操作 100% 被界面机制拦截（无可用入口）
- **SC-004**: 特性上线前已存在的历史项目 100% 可正常打开项目表单，无渲染错误
- **SC-005**: 字段 key 冲突时 100% 被拒绝保存并展示明确错误提示

## Assumptions

- 操作表单设计器的角色为管理员（管理员/投标管理员/投标系统管理员），与现有设计器权限一致，不新增权限模型
- 自定义字段仅作为附加信息采集与展示，**不参与**项目列表页、筛选、导出、统计报表及审批条件判断；如未来需要再单独立项
- 自定义字段可配置为必填或选填，沿用现有字段属性体系
- 自定义字段类型复用现有字段类型体系（文本、数字、日期、下拉等），不新增字段类型
- 本次范围仅限 project.basic、project.initiation、project.detail 三个表单范围；tender.entry 等其他范围的既有锁定机制（LOCKED_FIELD_KEYS / FIXED_GROUP_KEYS）不受影响
- 历史项目数据的自定义字段值初始为空，无需数据迁移回填
- 三个表单的系统预置字段清单以业务页实际硬编码消费的字段为准（实现阶段逐个梳理并与产品确认）
