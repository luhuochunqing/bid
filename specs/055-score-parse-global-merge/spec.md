# Feature Specification: AI 评分标准解析两阶段归并 + 表格行保真

**Feature Branch**: `agent/claude/score-parse-global-merge`

**Created**: 2026-08-26

**Status**: Draft

**Input**: 用户确认的中期治本方案——(4) 两阶段架构：召回允许重复，新增"全局归并 LLM 裁决"阶段重建结构；(5) 表格结构保真：评分表按行切分与直抽，一行 = 一个候选，从源头消灭"连续文本拼接"类 bug。

## 背景与问题（真实案例）

项目 1347 解析暴露两类管线级缺陷（PR !2408 只改展示层未触及根因）：

1. **重复项漏并**：同一评分条款（"根据用户提出的平台目录内商品的寻源需求编制响应保障方案…"）在结果中出现两次（S9"技术服务部分" + A2"技术方案"），另有残缺截断版（A1 是 S8 的后半段）独立成项。根因：合并策略要求 detail 归一化逐字相等且编号/维度信号一致，而 LLM 跨 chunk 输出的编号与维度天然漂移。
2. **独立项被吞并**：价格部分两个独立无编号评分项（"不平衡报价评审" 5 分 + "投标人提供上架商品价格管控方案" 4 分）被报价维度特判（同维度 + 无编号 → 无条件同一项）合并成一条 5 分项，4 分项静默消失。
3. **表格行被切断**：文档切片为 4000 字硬滑窗，评分表超长时表格行被拦腰斩断，产生残缺候选（A1 类）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全局归并裁决消除重复与误并 (Priority: P1)

投标经理触发 AI 评分标准解析后，系统在候选池去噪后增加一次"全局归并裁决"：把去噪候选池与评分章节原文全文一起交给 LLM，一次性重建最终评分项结构——哪些候选是同一项、维度归属哪个大项、编号如何对齐。同一条款的多次召回（含残缺截断版）归并为一项；同维度下各自完整的独立条款（各自含分值裁决）保持独立。

**Why this priority**: 直接修复用户报告的两个线上缺陷（重复 + 吞并），是本 feature 的核心价值。

**Independent Test**: 构造含重复召回候选与相邻独立价格条款的候选池 + 评分章节原文，调用归并裁决，验证输出清单无重复且独立项保留。

**Acceptance Scenarios**:

1. **Given** 候选池含同一条款的两次召回（detail 几乎逐字相同、维度不同），**When** 全局归并执行，**Then** 最终清单仅保留一项，维度取更完整召回的归属。
2. **Given** 候选池含"不平衡报价评审（5 分）"与"上架商品价格管控方案（4 分）"两个独立候选，**When** 全局归并执行，**Then** 两项均独立保留，分值分别为 5 与 4。
3. **Given** 候选池含某条款的完整版与从句中截断的残缺版，**When** 全局归并执行，**Then** 残缺版并入完整版，不单独成项。
4. **Given** 归并 LLM 调用连续两次失败，**When** 管线继续，**Then** 降级使用现有启发式合并结果，任务不失败（fail-open），并记录降级日志。

### User Story 2 - 评分表格行保真 (Priority: P1)

评分标准在招标文件中几乎总是表格。系统在切片与召回两个环节保真表格行结构：切片边界永不落在表格行内部；新增表格行直抽召回通道，markdown 管道表格逐行解析为候选（一行 = 一个候选），评审内容列与分值列正确对齐。

**Why this priority**: 残缺候选（A1 类）的源头治理；行级候选天然完整、天然不重复，为 US1 的归并提供高质量输入。

**Independent Test**: 构造含 20 行评分表（超长需切片）的 markdown 文本，验证每个候选 detail 均为完整表格行原文（不跨行截断），分值列提取正确。

**Acceptance Scenarios**:

1. **Given** 评分表章节超过单块上限，**When** 切片执行，**Then** 任意切片边界均位于表格行之间，不存在以半个管道行开头/结尾的切片。
2. **Given** markdown 文本含管道评分表（列：评分项/评审内容/分值），**When** 表格行直抽执行，**Then** 每行产出一个候选，detail 为该行评审内容逐字原文，weight 为分值列数字。
3. **Given** 表格行含合并单元格或空列，**When** 表格行直抽执行，**Then** 该行降级为整行原文作为 detail（不丢行、不编造列语义）。

### User Story 3 - 归并决策可观测 (Priority: P2)

运维/开发排查解析质量问题时，可通过任务日志看到全局归并的决策摘要：输入候选数、输出项数、合并了哪些组、丢弃了哪些残缺项、是否降级。

**Why this priority**: 归并是 LLM 非确定性环节，无日志则线上质量问题无法回溯定位。

**Independent Test**: 运行含归并的解析流程，检查日志输出含输入/输出计数与降级标记。

**Acceptance Scenarios**:

1. **Given** 解析任务完成归并，**When** 查看任务日志，**Then** 存在一条归并摘要日志（输入候选数 → 输出项数、合并组数、降级与否）。

### 边界情况

- 评分章节定位失败（文档无"评分"关键词区域）：归并上下文降级为全文前 N 字符截断，归并仍执行。
- 候选池为空或仅 1 项：跳过归并 LLM 调用（无归并价值），直接进入后续门禁。
- 归并输出含候选池中不存在的"新发明"评分项：仅当其 detail 能在评分章节原文中找到（逐字包含）才采纳，否则丢弃（防幻觉）。
- 归并输出丢失了候选池中的高置信客观项（有原文背书且未被合并）：以候选池为准回补，防 LLM 漏项。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-1**: 管线在"启发式合并 + 幽灵过滤"之后、权重闭环校验之前，执行全局归并裁决阶段；输入为去噪候选池与评分章节原文。
- **FR-2**: 归并裁决输出最终评分项清单，字段契约与现有候选一致（code/dim/detail/weight/scoreTypeGuess/sourceText/location）；detail 必须为招标文件逐字原文，禁止摘要改写。
- **FR-3**: 归并 LLM 调用失败（重试 1 次后仍失败）时，管线降级使用启发式合并结果继续，任务不失败。
- **FR-4**: 文档切片不得在表格行内部产生边界；超长表格按行边界子切分。
- **FR-5**: 新增表格行直抽召回通道：定位 markdown 管道表格块，逐行产出候选（一行 = 一候选），与既有四路召回并列进入合并。
- **FR-6**: 归并决策输出结构化摘要日志（输入/输出计数、合并组数、降级标记、幻觉丢弃数、漏项回补数）。
- **FR-7**: 既有质量门禁全部保留且作用于归并结果之后：幽灵过滤、权重非法剔除、100 分闭环回补、超载剔除、权重归一化、数量校验。
- **FR-8**: 归并 prompt 与输出契约遵循 spec 041 的 llm-output-schema 演进规则，新增契约需文档化。

### Assumptions

- 评分章节原文来源复用现有评分区域定位能力（`MarkdownScoreSectionLocator`）；定位失败时截断全文前 12000 字符作为裁决上下文。
- 归并为单次 LLM 调用（非逐项循环）；输入候选以紧凑 JSON 摘要形式嵌入 prompt。
- 表格行直抽仅在含"评分/评审/分值"语义的表格块上执行，避免全文档表格误入。
- 解析耗时增加一次 LLM 调用属可接受代价（分钟级任务）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-1**: 项目 1347 类文档重新解析后，"投标人提供上架商品价格管控方案"作为独立评分项存在且 weight=4；价格部分小计包含 5+4 两项。
- **SC-2**: 含重复召回的场景中，最终清单内不存在 detail 归一化后互相包含的两项。
- **SC-3**: 超长评分表切片后，所有切片边界均在表格行之间（可用纯函数单测证明）。
- **SC-4**: 归并降级路径（LLM 失败）下解析任务仍为 COMPLETED 且结果与现有管线一致（回归保障）。
- **SC-5**: 既有单测全绿；新增纯核心单测覆盖：归并 prompt 构建、表格行解析器、降级编排、幻觉过滤。
- **SC-6**: 解析总耗时相对现有管线增幅 ≤ 30%。

### 关键实体

- **ScoreCandidate**（既有）：候选评分项，归并输入与输出载体。
- **归并裁决输出**（新）：LLM 结构化输出，含最终清单与决策摘要（合并组、丢弃项）。
- **DocumentChunk**（既有）：切片产物，新增"表格行安全边界"约束。
