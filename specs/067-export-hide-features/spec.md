# Feature Specification: 甲方验收导出——未开放功能代码级剔除

**Feature Branch**: `agent/qoder/export-hide-features`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "将产品源代码导出给甲方客户做验收，先导出前隐藏未对甲方开放的功能，代码级剔除——路由 + 页面文件一并从导出包剔除，联动入口一并删除，死代码一并剔除，仅剔前端（后端 API 保留）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 剔除隐藏菜单对应的功能页面（Priority: P1）

交付负责人将源代码导出给甲方验收前，把"菜单已隐藏但页面代码仍在"的 8 个功能（客户商机中心、审计日志、可投标能力检查 BAR、站点台账、费用管理、合同借阅、投标结果闭环、知识库模板库）从代码库中彻底移除：访问这些功能的地址不再进入任何页面，对应的界面文件、组件、专属辅助模块不再存在于代码库中。甲方在系统里浏览、搜索代码时，看不到这些未开放功能的痕迹。

**Why this priority**: 这是本次导出的核心诉求——未对甲方开放的功能不能出现在验收代码中；且这些页面目前仅"藏菜单"，直达地址仍可访问，存在验收时被发现的风险。

**Independent Test**: 在剔除后的代码库中全局搜索这些功能的关键字与地址，确认无路由注册、无页面文件、无入口引用；启动系统逐个访问原地址，均不再渲染对应页面。

**Acceptance Scenarios**:

1. **Given** 剔除后的系统已启动，**When** 访问原"客户商机中心"地址，**Then** 不再进入该功能（不渲染该页面）
2. **Given** 剔除后的代码库，**When** 检查侧边栏菜单配置与路由表，**Then** 8 个隐藏功能对应的菜单项与路由条目均已不存在
3. **Given** 剔除后的系统，**When** 打开工作台"快速发起"，**Then** 不再出现"合同借阅"入口，但"资质借阅"入口仍正常可用
4. **Given** 剔除后的系统，**When** 打开项目详情页，**Then** 不再出现跳转"投标结果闭环"的入口
5. **Given** 剔除后的系统，**When** 打开系统设置页，**Then** 不再出现"审计日志"页签
6. **Given** 剔除后的代码库，**When** 检查知识库模块，**Then** 模板库页面及其专属组件已不存在，知识库其余子功能（项目档案、资质证书等）不受影响

---

### User Story 2 - 剔除从未接入系统的死代码页面（Priority: P2）

把代码库中"无路由、无引用、从未展示给任何用户"的孤立页面一并移除，使导出的代码库中每个页面都能被系统实际使用，避免甲方阅读代码时产生"功能是否存在"的困惑。

**Why this priority**: 死代码不影响运行，但会污染验收观感、增加甲方理解成本；优先级低于核心剔除诉求。

**Independent Test**: 对每个声称已剔除的死页面，在代码库中确认其文件不存在且无任何残留引用；系统原有功能回归测试全部通过。

**Acceptance Scenarios**:

1. **Given** 剔除后的代码库，**When** 检查分析模块，**Then** 旧版分析页面（旧数据看板、竞争情报、评分分析、ROI 分析的 4 个孤立页）已不存在，现役分析页不受影响
2. **Given** 剔除后的代码库，**When** 检查标讯模块，**Then** 从未接入的"标讯收藏列表页"、"市场预测页"已不存在，标讯列表/详情/收藏按钮等现役功能不受影响
3. **Given** 剔除后的代码库，**When** 检查文档模块与资源模块，**Then** 孤立的"文档组装页"、"资源日历页"已不存在，标书编辑器等现役功能不受影响

---

### User Story 3 - 剔除后系统完整回归无损（Priority: P1）

剔除动作完成后，系统所有仍对甲方开放的功能与剔除前完全一致：构建成功、自动化测试全部通过、无因删除产生的失效引用或运行时报错。

**Why this priority**: 剔除是破坏性改动，若引入回归，验收交付直接失败；与 P1 同级，是交付底线。

**Independent Test**: 在剔除后的代码库执行完整构建与全量前端自动化测试，全部通过；抽查主要业务页面（工作台、标讯、项目、知识库、资源管理、系统设置）可正常打开。

**Acceptance Scenarios**:

1. **Given** 剔除改动完成，**When** 执行前端构建，**Then** 构建成功，无缺失模块错误
2. **Given** 剔除改动完成，**When** 执行全量前端单元测试，**Then** 全部通过（被删页面的专属测试随之删除，非专属测试零失败）
3. **Given** 剔除改动完成，**When** 全局搜索被删页面/组件/辅助函数的名字，**Then** 无任何残留引用

---

### Edge Cases

- 某个被删页面的辅助模块（composable、helpers）同时被仍在用的功能引用时：只移除属于该页面独有的部分，共享部分必须保留（如工作台快速发起中的"资质借阅"逻辑与"合同借阅"逻辑混在同一对话框流程中，须精准拆分而非整体删除）
- 某个被删功能在权限树/角色菜单配置中出现时：配置项应同步清理，避免权限管理界面出现指向不存在功能的选项
- 删除后测试文件仍引用被删模块：该测试随页面一并删除；测试引用的是共享模块：共享模块保留、测试不删
- 后端接口保留导致前端无调用方：属预期（本次范围仅前端），不作为缺陷

## Requirements *(mandatory)*

### Functional Requirements

**隐藏功能剔除（P1）**

- **FR-001**: 系统 MUST 移除以下 8 个隐藏功能的访问路由：客户商机中心、审计日志、可投标能力检查（BAR）、站点台账、费用管理、合同借阅、投标结果闭环、知识库模板库
- **FR-002**: 系统 MUST 移除上述 8 个功能的页面文件及其专属子组件、专属辅助模块（仅被这些页面引用的 composable/helpers/scss）
- **FR-003**: 系统 MUST 移除指向上述功能的全部外部入口：工作台"快速发起"中的合同借阅入口、项目详情中的投标结果跳转、系统设置中的审计日志页签
- **FR-004**: 工作台"快速发起"借阅流程中的资质借阅能力 MUST 完整保留，不得因合同借阅剔除而受损
- **FR-005**: 菜单配置中的隐藏菜单集合与角色菜单配置 MUST 同步清理被删功能条目，不得残留指向不存在页面的配置
- **FR-006**: 知识库其余子功能（项目档案、案例库、资质证书、人员证书、仓库信息、业绩管理、品牌授权）MUST 不受模板库剔除影响

**死代码剔除（P2）**

- **FR-007**: 系统 MUST 移除以下从未接入的孤立页面：旧版数据看板、旧版竞争情报页、旧版评分分析页、旧版 ROI 分析页、标讯收藏列表页、市场预测页、文档组装页、资源日历页
- **FR-008**: 死代码剔除 MUST 仅限"无路由且无任何现役引用"的页面；若某文件被现役组件引用（如同名但位于共享组件目录），则 MUST 保留

**范围边界**

- **FR-009**: 本次剔除范围 MUST 仅限前端；后端对应 Controller/Service/API 接口全部保留
- **FR-010**: 剔除 MUST 不改变任何仍开放功能的可观察行为

**验证**

- **FR-011**: 剔除完成后前端构建 MUST 成功
- **FR-012**: 剔除完成后全量前端自动化测试 MUST 通过；被删页面的专属测试文件 MUST 随页面一并删除
- **FR-013**: 剔除完成后，全局搜索被删页面、组件、辅助函数名称 MUST 无残留引用

### Key Entities

- **隐藏功能**：菜单配置中列入隐藏集合、菜单不展示但路由与页面代码仍存在的功能（8 个）
- **孤立页面**：既无路由注册、也无任何组件引用的页面文件（8 个）
- **联动入口**：其他现役页面中跳转或打开被删功能的按钮/页签/快捷项

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验收代码包中，未开放功能的路由条目数为 0、页面文件数为 0、外部入口数为 0
- **SC-002**: 验收代码包中，孤立页面数量为 0（每个存在的页面均可从系统某处到达）
- **SC-003**: 剔除后前端构建一次成功，失败构建数为 0
- **SC-004**: 剔除后全量前端自动化测试通过率 100%（删除的专属测试除外）
- **SC-005**: 抽查的 6 个主要业务页面（工作台、标讯中心、投标项目、知识库、资源管理、系统设置）功能表现与剔除前一致
- **SC-006**: "快速发起"中的资质借阅、标讯列表中的收藏按钮等易误伤的共享能力，验证通过率 100%

## Assumptions

- "未对甲方开放的功能"以代码中既有的隐藏菜单配置（hiddenApiMenuNames）为准，共 8 项；用户未提供额外清单
- 后端接口保留属有意决策：本次交付口径为"仅剔前端"，后端死接口不影响验收且降低改动风险
- 剔除在独立任务分支上进行，不动基准分支；导出包从该任务分支打包
- 死代码清单以 2026-09-22 对 `agent/qoder-init` 基线的引用分析为准；若打包前基线有更新，需重新核对引用关系
- 文档目录（docs/、.wiki/、specs/ 等）在最终打包阶段整体排除，不通过代码剔除实现
