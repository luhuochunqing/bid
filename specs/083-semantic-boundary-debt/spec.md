# Feature Specification: Semantic boundary 技术债收口

**Feature Branch**: `agent/claude/semantic-boundary-debt`
**Created**: 2026-11-10
**Status**: 用户已批准实施
**Input**: 用户批准逐方法拆分清单并要求开始实施；不推送、不建PR、不部署。

## User Scenarios & Testing

### US1 - 契约与观察语料分离 (P1)
维护者修改规则时，只由明确业务、结构化解析与原位证据契约阻断；语言变形作为显式运行的观察语料。
独立验证：所有旧方法及参数有去向；迁移阶段完整执行原预期。默认运行排除语料、显式运行可恢复语料。

### US2 - 可读的纯核心 (P1)
维护者可从命名片段读懂边界；纯结构修改前后全部旧输出相同。
独立验证：纯结构阶段同组测试全绿，生产Java每行≤120字符且每文件≤300行。

### US3 - 无明确主体转人工 (P1)
未知主语的跨句状态不由规则推断归属，转人工并保留证据；明确同句对象缺陷及既有放行决策保留。
独立验证：明确对象、裸续句、跨页裸续句、明确其他对象四类最小范围契约及既有引擎入口回归。

## Requirements

FR01 以已批准逐方法清单为迁移依据，保留业务、HTML、JSON契约；变形语料完整迁移而非删除。
FR02 结构重构与行为收口分开验证、分别记录；不得靠更改旧断言伪造等价。
FR03 无明确证书主体的续句统一人工；无新自然语言变形枚举、无跨句指代状态机补丁。
FR04 四维度保持：系统折扣率仍人工核对；明确免保证金不进视觉复核；OCR完整要素/附件边界保持；企业资质有效匹配可放行但明确同句缺陷仍拦截。映射依据为decisions.tsv 2026-11-08 design-alignment与unblock-policy记录，不另赋历史未定义的A/B/C/D字母。
FR05 保留原页码、摘录、证据与明细，不新增Mock业务路径或外部状态依赖。
FR06 审查复用!2994历史注入和熔断，不清零、不自行allow-rerun，不受语言语料失败驱动扩规则。

## Success Criteria

AC01 151个旧方法及所有参数输入均可追溯，迁移全量实际执行与原断言一致。
AC02 默认运行不执行heuristic-corpus；显式运行实际执行大于0项；三类契约运行不遗漏。
AC03 纯结构阶段所有迁移测试输出不变，两个policy及拆分文件符合120字符/300行限制。
AC04 未明确主体的同页/跨页续句输出人工，明确同句缺陷不放行，四维度主路径保持。
AC05 相关域、架构、构建和三技能审查有当前内容证据；未验证项如实记录。

## Assumptions and Boundaries

清单参数#1为代表项，不声称所有字符串来自真实原件；未核实来源不升级真实样本。80～100为规模目标，不以凑数删除必要证据断言。无数据库/API/部署变更。既有原件与客户数据不入库。
