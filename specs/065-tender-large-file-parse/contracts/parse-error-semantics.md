# Contract: 解析失败语义（招标侧）

**Feature**: `specs/065-tender-large-file-parse` | **Date**: 2026-09-18

> 沿用 spec 045 `api-error-semantics.md` 语义分类（业务类可自救 vs 资源类联系管理员），本文件只增招标侧两行。

## 后端 → 前端错误语义

| 场景 | HTTP | `msg` / `lastParseError` 文案 | 用户动作 |
|---|---|---|---|
| 无可用正文（未上传） | 400 | `请先在立项阶段上传招标文件`（不变） | 回立项上传 |
| 文本量超限（新增） | 400 | `招标文件文本量超过上限（约 500 万字），无法解析，请检查是否误传或拆分文档` | 检查误传/拆分文档后重传 |
| 配额超限（复用） | 400 | `招标文件过大超出服务器处理配额，请联系管理员`（`TenderFileQuotaException.MESSAGE`） | 联系管理员 |
| 读取失败（既有） | 400/FAILED | 有底稿则回退底稿（无感）；无底稿按读失败文案 | 点重新解析或检查文件 |

## 触发面

- `POST /api/.../parse`：无源/超限时 400 + 上表文案，且先落 `FAILED` 任务（防打开抽屉自动重打循环，沿用 spec 043 T018 语义）。
- `GET /items`：`meta.lastParseStatus=FAILED` 时 `meta.lastParseError` 为上表文案；抽屉失败态原样展示 + 次行动作文案（见前端契约）。
- `GET /parse/status`：轮询终态与上表一致。

## 前端文案契约（C1/C2）

- 立项上传区 tip：`支持 PDF/Word，≤512MB 上传；解析按文本量（约 500 万字上限），扫描大 PDF 压一下一般即过`。
- 上传超配额拦截：`文件大小超过限制（512MB），请压缩后重新上传`（上传侧口径，配额值来自配置）。
- 抽屉失败态：主句透传后端文案；次行：`扫描大 PDF 可压缩后在立项未提交前替换；已提交需联系管理员`；按钮统一为`重新解析`。
