  3. DB：**无 DDL**（列保留，仅停写文本）
- **兼容性**：存量已填写的 GAP 文本仅后台留存，前端不再展示；历史附件引用正常可查。

## 八、风险与注意事项

1. **双表单形态**：标讯评估表有「动态 schema + 静态降级」两套渲染，改字段必须两处同步，且动态 schema 走 DB 迁移（V1167 模式），漏改 schema 会导致动态表单下需求不生效。
2. **GAP 改造的边界**：只下线文本框，附件组件与 `EVALUATION_GAP` 文档链路、CRM 回填（CO-262）一律不动；注意 `ProjectPlanGapUpload` / `AdaptiveGapUpload` 组件内部如耦合了文本字段需解耦。
3. **立项带入链路回归**：`EvaluationToInitiationMapper` 移除 GAP 映射行时，需回归其他 8 个字段带入不受影响（CO-323 历史教训：该链路改动易引入整行丢失）。
4. **纯核心层契约**：`TenderEvaluationFormPolicy` 等 FP-Java 纯核心校验是业务规则唯一权威，GAP 文本相关校验清理须在此层完成，service 层不得遗留重复逻辑。
