## 4. 监控体系

### 4.1 健康检查

| 检查项 | 地址 | 频率 | 预期状态 |
|--------|------|------|---------|
| Actuator 总体健康 | `http://127.0.0.1:18080/actuator/health` | 每 5 分钟 | UP（sidecar DOWN 为已知非阻断） |
| 就绪检查 | `http://127.0.0.1:18080/actuator/health/readiness` | 每 5 分钟 | UP |
| 存活检查 | `http://127.0.0.1:18080/actuator/health/liveness` | 每 5 分钟 | UP |
| DB 组件 | 同上 health 响应 | 每 5 分钟 | UP（MySQL） |
| Redis 组件 | 同上 health 响应 | 每 5 分钟 | UP（6.2.19） |

> **说明**：当前 `/actuator/health` 整体返回 DOWN，仅因 sidecar 组件（`http://localhost:8000`）不可达。sidecar 为可选组件，`fallbackAvailable: true`，不影响核心业务。巡检时需分别检查各组件状态，不可仅凭总体状态判定。

### 4.2 日志监控

| 日志类型 | 路径 | 关注级别 | 说明 |

| Nginx 错误日志 | `/var/log/nginx/error.log` | error | upstream 超时、连接重置 |

## 6. 应急响应流程

### 6.1 事故分级

| 级别 | 定义 | 示例 |
|------|------|------|
| P0 | 核心业务不可用，影响全部用户 | 后端宕机、数据库不可达、登录全失败 |
| P1 | 重要功能不可用，影响部分用户 | 项目列表无法加载、标讯导入失败、权限系统异常 |
| P2 | 次要功能异常，有变通方案 | 某报表导出失败、某非核心页面报错 |
| P3 | 体验问题，不影响业务 | UI 错位、文案错误、性能略慢 |

### 6.2 响应目标

> **说明**：以下为试运行期的**响应目标**，非合同 SLA 承诺。实际响应时间取决于问题复杂度、人员可用性和根因定位难度。

| 级别 | 响应目标（业务时段） | 解决目标 | 升级条件 |
|------|---------------------|---------|---------|
| P0 | 目标 < 15 分钟 | 目标 < 2 小时（**尽力**，不承诺） | 30 分钟未恢复升级 L3 + 客户运维 |
| P1 | 目标 < 30 分钟 | 目标 < 4 小时（**尽力**，不承诺） | 2 小时未解决升级 L3 |
| P2 | 目标 < 2 小时 | 目标 < 1 个工作日 | 次日未解决升级 L2 |
| P3 | 目标 < 1 个工作日 | 按周排期处理 | — |

### 6.3 P0/P1 处理流程

1. **发现**：监控告警 / 用户反馈 → 系统管理员确认级别
2. **响应**：L1 立即检查服务状态、日志；L2 同步介入
3. **定位**：根据日志与 Sentry 定位根因
4. **处置**：
   - 可重启恢复 → 先恢复服务，再分析根因
   - 需代码修复 → 走 §9 变更管理流程
   - 需回滚 → 执行 ROLLBACK_RUNBOOK
5. **验证**：恢复后执行 P0 验证清单（前端 200 + API 路由 + 健康检查）
6. **复盘**：P0/P1 事故 24 小时内输出复盘文档（`postmortem-YYYY-MM-DD-*.md`）

### 8.3 FAQ（试运行常见问题）

**Q1：登录提示"没有权限访问该系统"怎么办？**
A：该用户在 CRM/OSS 侧未分配 bid-platform 权限。联系 CRM 管理员授权后，等待下一次 OSS 同步（或手动触发同步）即可登录。

**Q2：文档洞察功能无法使用？**
A：当前 sidecar（Markitdown）服务未部署，docinsight 功能处于降级状态，已自动回退到本地 textutil。试运行期内将排期部署 sidecar。

**Q3：OSS 用户信息变更未实时同步？**
A：Kafka 增量事件尚未配置，当前依赖全量同步。试运行期每日触发全量同步补偿。配置 event-busserver 后将恢复实时同步。

**Q4：AI 相关功能（标书生成、智能补全）无法使用？**
A：当前生产环境 AI API Key 尚未配置（`apiKeyConfigured=false`），AI 相关功能暂时不可用。需开发团队或客户运维配置真实 deepseek API Key 后复测。详见 §7 R6。

**Q5：发现 UI 错误或文案问题如何反馈？**
A：通过平台内用户反馈入口或内部 IM 群提交，标注为 P3 级别，将在每周排期处理。

| 触发条件 | P0 事故且无法在合理时间内修复 |

| 用户反馈处理 | P0 问题 100% 解决，P1 问题 ≥ 80% 解决 | 反馈台账核对 |
