## 三、方法论沉淀

### 3.1 正确的做法（功能级权限审计）

```
文档要求（飞书权威基线）
    ↓
逐功能点对照代码实现（Controller 注解 + Service 层逻辑）
    ↓
差距判断（角色覆盖/数据范围/状态收口/人员维度）
    ↓
契约测试锁定（防漂移）
    ↓
业务确认 gap → 修复
```

### 3.2 错误的做法（机械迁移，被纠偏）

```
hasAnyRole → hasAuthority（语法换写）
    ✗ 用文档不存在的权限键（system.admin）
    ✗ 忽略 Service 层数据范围/状态收口
    ✗ 掩盖真实问题（接口重叠/越权）
    ✗ 测试断言变成"假性"（CaCertificate 假性 403）
```

### 3.3 关键教训

1. **权限不只是 Controller 注解**——文档的权限是 4 维（角色×功能×数据范围×状态），真正的权限在 Service 层（AccessGuard/Policy）。只改注解会掩盖 Service 层问题。

2. **契约测试是防漂移的唯一手段**——50 个测试锁定当前行为，未来任何重构（误放行/误收紧）立即变红。

3. **`@WebMvcTest` 切片的权限断言要看清测哪层**——mock 掉 Service 后，"403 断言"可能基于不完整 mock（CaCertificate 假性 403）。

4. **业务确认是闭环关键**——4 个 gap 通过 BBB A 确认，避免了开发侧擅自决策。

5. **审计文档 vs 代码的一致性**——飞书文档 V1.0 是权威，但 3 处文档滞后于代码（标讯侧 BBB），需同步更新飞书。
