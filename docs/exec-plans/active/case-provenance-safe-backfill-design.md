# 案例来源生产安全回填设计

## 目标

为生产库中来源五字段全部为空的 ACTIVE 知识案例建立可证明、可预演、可审计、可回滚的补齐流程。任何无法从原始标书唯一证明来源的案例保持不变。

## 不可变安全规则

1. 默认模式为 `preview`；没有显式 `apply` 时不得调用持久化端口。
2. 仅处理 `source_section_title`、`source_section_path`、`source_section_index`、`source_document_name`、`source_page_number` 五字段全部为空的记录。
3. 任一来源字段已有值时整条跳过，不覆盖、不修正、不清空。
4. 仅在原始标书可用且正文片段唯一落入合法章节时产生 `FILLABLE` 决策。
5. 零命中、多命中、正文为空、项目缺失、标书不可用或解析失败均保持原值。
6. 禁止用评分项标题、正文首句、模型生成标题或固定字符串兜底。
7. 正式写入必须使用扫描快照和“来源五字段仍全部为空”的条件更新；任何漂移使整批事务失败。

## 执行模式

### Preview

- 命令显式选择 `preview`，也是唯一默认模式。
- 读取候选、项目和原始标书，计算决策但不调用 `saveAll`。
- 输出批次 ID、候选总数、审计文件摘要和分类计数。
- 生成 JSONL 与 CSV 审计文件；不记录完整案例正文，只记录受限证据摘要及其哈希。
- 同时生成拟回滚 SQL 工件，供审查写入目标和条件；preview 阶段不会执行该 SQL。

### Apply

- 必须显式选择 `apply`，并提供同一 preview 产生的批次 ID、候选数量和审计文件 SHA-256。
- 程序重新扫描并重新计算，只有与 preview 清单完全一致时才允许进入写入。
- 持久化采用按项目独立事务、快照条件更新和来源全空守卫。
- apply 不在本任务当前授权范围内，完成实现后仍只执行生产 preview。

## 审计决策

每个扫描案例只能落入一个决策：

- `FILLABLE`：有唯一、合法、可证明的来源，preview 中仅列出拟写值。
- `SKIP_EXISTING`：五字段任一已有值，保持不变。
- `UNRESOLVED`：原标书可用但无法唯一定位，保持不变。
- `PROJECT_UNAVAILABLE`：项目或标书不可用，整项目保持不变。
- `ORPHAN`：缺少来源项目 ID，保持不变。
- `STALE_AT_APPLY`：apply 时快照或来源空值条件已变化，拒绝写入。

计数必须闭合：扫描总数等于所有决策数之和。

## 回滚工件

- 对每条 `FILLABLE` 生成带案例 ID 和本次拟写五字段当前值守卫的反向 SQL。
- 只有数据库当前值仍等于本批写入值时，回滚才把五字段恢复为 preview 时的原值（本流程限定为全空）。
- 回滚 SQL 包含批次 ID 注释、事务边界、预期影响行数和异常时 `ROLLBACK` 操作说明。
- 回滚工件生成不代表授权执行。

## 兼容与禁用旧入口

旧 `--recompute-case-provenance=true` 具备清空行为，不能继续作为生产入口。新实现必须使该参数明确拒绝并提示使用安全模式，避免运维误触。既有服务可以保留内部兼容方法供测试迁移，但生产 CLI 只能暴露安全 preview/apply 契约。

## 验证

- RED/GREEN 测试覆盖 preview 零写入、只补全空来源、已有部分来源跳过、无法定位不清空、审计计数闭合。
- 端口测试覆盖来源全空条件更新与扫描快照漂移拒绝。
- CLI 测试覆盖默认 preview、旧参数拒绝、apply 缺少预演凭证拒绝。
- 审计工件测试覆盖脱敏、SHA-256、CSV/JSONL 一致性及守卫式回滚 SQL。
- 生产只读预演前后执行只读计数核对，证明数据库无写入。

## 当前交付边界

本任务实现并验证安全回填程序，随后仅对生产执行只读 preview。不会执行 apply、不会部署新版本、不会运行回滚 SQL；这些动作需要独立授权和发布证据。
