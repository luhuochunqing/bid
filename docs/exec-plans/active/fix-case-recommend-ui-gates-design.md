# 案例推荐前端误判与结果隐藏修复设计

## 背景

测试环境真实 E2E 表明：项目 1388 的“TECH_QUAL 质量管控”因详细条款出现“认证”被前端误判为资质证书项；“BIZ_FIN 经营及财务状况”的有效推荐分数集中在 32–37，接口返回 165 条，但前端 `score >= 50` 二次过滤后显示 0 条。

## 目标与范围

- 前端不再隐藏后端已经判定有效的低于 50 分推荐结果。
- 结果数展示接口返回的 `total`，而不是当前页卡片数。
- 普通技术/质量条款中的泛化“认证”不再触发资质证书提醒。
- 明确要求提交资质证书、证书复印件或扫描件的评分项继续显示提醒。
- 仅修改 `AiRecommendDrawer.vue` 及其组件测试；不修改推荐算法、API 契约、数据库或历史数据。

## 设计

`filteredCases` 在选择评分项后直接使用接口返回的 `cases`。后端 `ScoreItemCaseRecommendAppService` 已执行 `matchScore > 0` 的业务准入，前端不再叠加未经契约声明的 50 分门槛。组件保存响应 `total`，选择评分项时用它显示总命中数；默认推荐及失败分支重置该值，避免旧请求数量残留。

资质提示采用“标题优先、正文证据补充”的窄判定：评分项名称明确包含资质、证书、体系认证、ISO、许可、执照或管理体系时直接判定；详细条款仅出现普通“认证”不足以判定，必须出现资质证书、资格证书、体系认证、ISO、许可证、执照、证书复印件或证书扫描件等明确证书对象。这样保留真正证书项的引导，同时避免“强制认证产品质量管理”等技术方案语境误伤。

## 验收

1. API 返回 32、37 分案例及 `total=165` 时，两张卡片均展示，结果标签为“165 个结果”。
2. `TECH_QUAL 质量管控`、详情含“强制认证产品质量管理”时不显示资质提醒。
3. ISO 管理体系认证且要求提供证书复印件时仍显示资质提醒。
4. `AiRecommendDrawer.spec.js` 全量通过，前端构建通过。
