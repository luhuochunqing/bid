# 评分走立项招标文件

不在规格里、实现时定下来的选择：

- 立项 `TENDER` 优先于 Bid Agent `TENDER_FILE`，再兜底旧快照正文。
- 不新建快照表，不调 Bid Agent 导入。解析时现读立项文件再抽正文。
- OBS（`obs-direct:`）用已有签发器拿预签名 URL 再 GET 字节，避免再铺一条下载网关。
- 自动解析门闩：仅当从未有过 PARSE 任务（`lastParseStatus == null`）且无评分项时，打开抽屉自动**新建**解析。PENDING/PROCESSING 跟随已有任务（复用并轮询），不算新建。COMPLETED 不自动打。FAILED 展示 `lastParseError`，再跑必须点「重新解析」。
- 没有可用正文：400 并落 FAILED。无文件文案为「请先在立项阶段上传招标文件」；超大且无底稿为「招标文件超过 50MB，无法解析」。
- 远程下载复用一个 `HttpClient`，先看 Content-Length，再流式累计，超过 50MB 放弃该来源并尝试底稿。
- `hasSource` 与 `resolve` 同一套成功条件：立项抽出非空正文，否则非空快照。

## 产品决定

编制页 / 流程卡上的「启动 AI 生成初稿」入口已下线，这是产品决定，不是事故回滚。Bid Agent 后端先留着，不在这条产品路上。

现行评分路径：

1. 立项阶段上传招标文件（`TENDER`）
2. 打开「AI 评分标准解析」抽屉（从未解析过则自动一次，否则点「重新解析」）
3. 编制阶段上传投标文件后做实际打分
